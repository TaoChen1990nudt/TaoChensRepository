## Phase 77 — 双击 ghost 换层去编辑

**需求**（用户原话）：在当前图层显示另一个图层作为 ghost note 的情况下，可以双击 ghost note
进入另一个图层进行编辑。

### 一、先划清"不变"的那条线

ghost 点穿是 P1/P20 立的规矩：看不见的图层不能被抓住。这条不动——`getEditableNoteIdAt()`
和所有手势命中仍然只看活动层。新增的只是**双击**上的一条路：双击是"让我过去"，不是"我要抓"，
两个动词。

### 二、接在哪

`handleDoubleClick()` 的顺序原来就是"活动层的东西先问，问完才是空白"：

```
采样块 → 音符 → 组框 → 组名 → （空白：退出组编辑）
```

这个顺序不是随便排的，它就是绘制顺序的倒影：`drawGroupBands → drawSamples → drawNotes →
drawGroupFrames → drawGroupLabels`，而 ghost 是 `drawNotes` 的 pass 1，画在所有活动层内容
下面。所以新分支插在**组名之后、空白之前**——压在 ghost 上面的东西都有优先权。

```cpp
if (const auto ghost = hitTestGhost (pos); ghost.layerIndex >= 0)
{
    stack.setActiveLayerIndex (ghost.layerIndex);      // 换层，会清场
    ...  selectGroup(gid, occ) + enterGroupEdit(gid)   // 组里的
    ...  setSelection({id}) / setSampleSelection({id}) // 不在组里的
}
```

**顺序是语义的一部分**：`setActiveLayerIndex()` 触发 `layersChanged()`，那里无条件关掉
`editingGroupId` 并清空选区（P73：撤销/加载/换层都从这条路进来）。所以选择必须写在换层
**之后**，否则写完就被清掉。

### 三、`hitTestGhost()`

倒序扫层（`drawNotes` pass 1 是升序画的，后画的在上 → 倒序第一个命中的就是看得见的最上面
那个），跳过活动层（它由自己的命中测试回答）和眼睛关掉的层（不可见的东西不可点）。层内先
音符后块——`drawSamples` 在 `drawNotes` 之前，块在音符下面。

### 四、自检 641 → 647（六条）

1. 单击 ghost 仍然点穿（`getEditableNoteIdAt == -1`，活动层不动）；
2. 双击不分组 ghost → 换层 + 选中它 + **打开它的包络**（`onNoteDoubleClicked`）；
   最后这半条是回头补的：在那一层上双击同一个音符会打开包络检查器，跨层只做换层
   就成了两套语义。同一手势、同一对象、同一个结果。
3. 双击组里的 ghost → 换层 + 进组 + **整次出现**被选中（P74）；
4. ghost 上压着活动层自己的音符 → 双击改的是活动层那个，不跳层；
5. （4b）只有活动层在那有东西时，`getGhostLayerAtForTest()` 答 -1；
6. 眼睛关掉的层，双击它原来的位置不跳过去。

### 五、咬测 6 处

| 植入缺陷 | 结果 |
|---|---|
| `hitTestGhost` 不跳过活动层 | 1 条挂（`1（应为 -1，活动层是 1）`） |
| 不看 `isLayerShown` | 1 条挂（`层 0 / 命中 2`） |
| 跳过去但不进组 | 1 条挂（`0 / 组 -1 / 选中 2 个`） |
| 只选单个成员（`setSelection` 代替 `selectGroup`） | 1 条挂（`0 / 组 484 / 选中 1 个`） |
| 整条 ghost 分支关掉 | 2 条挂 |
| 不触发 `onNoteDoubleClicked` | 1 条挂（`包络 -2:-2（应为 0:1）`） |

第一处**第一次咬空**（零条挂）：活动层的命中排在前面，手势永远走不到那条守卫。按项目老规矩
给了一个能直接问它的钩子 `getGhostLayerAtForTest()`，才咬得住。

### 六、四条夹具教训（都写进 PITFALLS P77-A 了）

1. 测不到的守卫要么删、要么给入口，不能留着当"保险"。
2. 用例撞像素 → 空断言：第 5 条原本拿 `plain` 的位置，可第 4 条刚在同一像素加了 `shadow`。
3. 场景串味：第 3 条接在第 2 条后面，而第 2 条已经把活动层换走了，`grouped` 不再是 ghost。
4. "这一刻像素上有 ghost"要按层问：`shadow` 那个像素上另一层**确实**有音符，答 0 是对的。

### 七、结果

`647 ALL PASSED / 0 FAIL`，`EXIT=0`，零 error 零 warning，`grep BITE Source/` 无残留。
`docs/p77.png` 已确认。`formatVersion` 仍 25（纯视图/手势，不动工程文件）。

### 八、边界

- **只对双击生效**：拖、框选、橡皮、刻刀都还是只看活动层。跨层批量操作没做。
- **包络只为不分组的那一个打开**：组成员双击是"打开组"（P73），包络要再双击一次——
  和它在自己那一层上完全一样。
- **ghost 的组框和组名不能双击**：`getGroupFrameAt()` / `getGroupLabelAt()` 只认活动层，
  所以在别的层上双击组框不会跳过去。用户这次说的是音符，块也顺手支持了，组框没动。
- **换层后视口不动**：滚动位置和缩放保持原样。目标音符在换层后可能在视口外（同一次双击
  自己滚过去是另一件事，没做）。

# Phase 78 — 双击采样块 = 打开它的包络框

## 一、需求与现状

> 双击采样也要能打开采样包络窗

采样块从 P49 起就有一条曲线（音量 + 声相，`SampleEvent::volumeCurve` / 第二条曲线），
但**唯一的入口是块右上角那个 12 px 的 chevron**。块的身体本身就在说"我是可以改形状的
东西"，双击它是所有人第一反应；而且音符那边双击打开的就是包络检查器（P77 刚把这条
补齐到跨层）——同一个动词在两种东西上给出两种结果，本来就不该长期存在。

现状确认：`handleDoubleClick()` 的采样分支只处理"闭组 → 进组"，未分组的块落下去会
掉进 `hitTestActiveLayer`（音符），块里没音符时什么都不发生。

## 二、实现

```cpp
if (auto* clip = hitTestSample (pos))
{
    if (clip->groupId >= 0 && clip->groupId != editingGroupId) { 进组…; return; }
}

if (auto* hit = hitTestActiveLayer (pos)) { …音符… return; }

//-- Phase 78
if (auto* clip = hitTestSample (pos))
{
    openSampleAutomation (stack.getActiveLayerIndex(), clip->id);
    return;
}
```

**位置就是绘制顺序**：`paint()` 里 `drawSamples` 在 `drawNotes` 之前，块画在音符
**下面**，所以"后画的先回答"→ 音符先、块后。第一版我把这段放在音符之前，理由写反了
（"块是先画的"= 块在下层），被咬测 2 和用例 2 一起抓住。

ghost 块同步补上（P77 的对称）：换层之后不是组成员时，除了 `setSampleSelection` 还要
`openSampleAutomation(ghost.layerIndex, clip->id)`——那个手势在它自己那一层上就是这个
结果，只做换层等于少做一半。

## 三、自检 647 → 653（6 条）

1. 双击不分组、没人压着的块 → 框开，且音符包络**没**被打开；
2. 连双击另一个块 → 只剩后一个的框（P49 的"一次一个浮窗"对新入口重新问一遍）；
3. 块上压着音符时双击 → 打开的是**音符**的包络，块的框关着（顺序判据）；
4. 双击**闭组**里的块 → 只进组，框不开（"让我进去"不能被编辑器挡住）；
5. 进组之后再双击同一个块 → 这时才是开框；
6. 双击 ghost 块 → 换层 + 开框。

## 四、咬测 4 处

| 植入的缺陷 | 结果 |
|---|---|
| 采样分支不打开框 | 3 条挂（`-1（应为 1）`、`-1（应为 2）`、`-1（应为 3，组 485）`） |
| 把分支提到音符命中之前 | 2 条挂（`-2 / 框 开着`、`485 / 框 开着`） |
| 进组时顺手开框 | 1 条挂（`485 / 框 开着（应为 485 / 关着）`） |
| ghost 分支不打开框 | 1 条挂（`层 0 / 框 -1（应为 0 / 1）`） |

第 2 条最值钱：它挂的不是"有没有打开"，而是"打开的是谁的框"。断言若只写
`isSampleAutomationOpen()`，这个缺陷会以 PASS 活下来。

## 五、夹具的第三次同一个坑

ghost 块先后放在 pitch 48 和 84，两次都落在可见网格外——`rect 96 59.8 192 36.4` 的
中心 y=78 正好压在 `grid` 的上边界（`grid 96 78 …`），`getGridArea().contains()` 卡在
边界上。加了一行诊断把 rect / gridBounds 打出来才看见，改到 pitch 78 立刻过。
P76 记过同一件事（`not armed`），这是第三次——**用屏幕坐标先打印几何，别猜**。

## 六、边界

- **只对双击生效**：dragging、框选、橡皮、刻刀完全不变；chevron 的 toggle（开/关）
  也保持原样，双击永远是"开"、不做 toggle。
- **双击块的边缘**也会开框（`handleDoubleClick` 不看按下抓的是边还是身体）。想拖边就
  直接拖，双击本来就意味着"打开"。
- **双击 chevron 会开→关→开**：第一击 toggle 一次、第二击再 toggle 一次，最后双击事
  件把它打开。结果正确，过程有一次多余重绘，没有处理。
- **闭组里的块必须先"进去"才能开框**，和 P73 一致；要一次到位得先点空白退组（那样
  块就回到闭组状态，还是要先双击进组）——这是"组是对象"的代价，不是这次的缺陷。

# Phase 78（续）— 推翻重做：要的是窗口，不是内联框

## 七、用户的一句话把方向掰回来了

第一版把双击接在 P49 的内联曲线框上——贴着块的窄条，能改曲线，以为这就是"打开包络"。
用户随后发来截图：音符包络窗（标题、`id 1 · Layer 1 · D#5 · beat 2.50 · len 1.00 · 5 pts`、
输出下拉、大画布、ADSR/渐弱/直线、底部提示），一句"我是想让采样块被双击后打开这样的编辑框"。

这不是"没说清"。需求里的名词是**窗**，代码里采样根本没有窗——只有一条窄条。名词对不上，
就是该新建东西的信号，我拿近亲顶替了。同一个动词（双击）落在两种对象上，反馈量级不能一个
是窄条、一个是窗口：用户会认为其中一个是 bug，而它确实被报成了 bug。

## 八、SampleEnvelopePanel 的构成

新组件 491 行 .cpp + 头，452×314，和 `NoteEnvelopePanel` 同尺寸、同一套行距（kEditorX/Y/H、
kPresetY/H/W/Gap 全部照抄），因为两个窗口会出现在同一个角落，行差 2 px 就像两种东西。

- **标题**：「采样包络」+ 图层色圆点。
- **身份行**：`id 1 · 层名 · 文件名 · beat 2.00 · len 4.00 · 2 pts`。
- **右上两枚切换**：「音量 / 声相」，写 `SampleEvent::automationTarget`——P50 的字段，内联框和
  工程文件都读同一个，所以两档编辑器不会对"当前是哪条曲线"各说各话。
- **输出行**：写 `outputSlotId`，名字与 badge 由 `routing::resolveSample` 解释（采样器 / 跟随图层 /
  采样器失效），绝不在这里自己算路由。
- **曲线区**：直接复用 `EnvelopeEditor`，`setEnvelopeSource` 每次返回 `&sample->activeCurve()`。
- **预设**：ADSR / 渐弱 / 直线。**「直线」随目标而变**——音量给 `makeFlat()`（1.0），声相给
  `makeIdle(0.5f)`（中置）。一个只会写 1.0 的按钮在声相上就是硬右。
- **底部提示**：`点击空白加点 · 拖动调整 · 右键删点 · Esc 关闭`（没有 Ctrl+D，采样不支持复制块）。

为此给 `EnvelopeEditor` 开了两个小口：`setEmptyText`（空态文案）与 `setCaptionName`（右上角
读数 pill，如"声相 0.50"）。后者是必需的：两条曲线共用一套形状语言，却对 1.0 有不同解释。

## 九、接线

`PianoRollComponent::onSampleDoubleClicked`（新回调）→
`MainComponent::openSampleEnvelopePanel()`（贴着块放、翻边、夹进窗口，和音符窗同一套规则）。

  两档承诺（快速一调 vs 打开编辑）都保留。

## 十、自检 653 → 659（12 条）

手势那一半 6 条：问对人 / 内联框被收掉 / 音符优先 / 闭组只进组 / 进组后开窗 / ghost 换层开窗。

# Phase 79 — 三个名字，一份数据

## 一、用户要的那句话

> 「要可以更改图层、音源和编组的名称，采样音源改名后，对应的钢琴窗上的音源实例也要改名，
> 编组栏里的编组框改名后，对应的钢琴窗上的编组也要改名。」

字面上是四件事：图层可改、音源可改、编组可改，加上跨视图一致。真正要回答的是最后半句：
**"跟着改"到底有几处？**

## 二、先数副本，再写同步代码

把三个名字的字段追一遍：

| 名字 | 唯一字段 | 谁在读 |
|---|---|---|
| 图层名 | `Layer::name` | 图层栏行、钢琴窗图层头、路由、机架"挂载"读数 |
| 编组名 | `NoteGroup::name` | 编组栏行、钢琴窗组框标题 |
| 音源名 | `SynthSlot::name` + `pluginName` | 机架卡、路由下拉、采样块头的"→ 槽名" |

三个都是**一份数据多处读**。钢琴窗组框标题每次 `group->getName()` 读同一个字段，
所以"编组改名后钢琴窗组框跟着改"**不需要任何同步代码**——它本来就是同一份。

真正是副本的只有一处：`SampleEvent::name`。采样块导入时把槽名抄进自己身上
（P27 之后块头写「块名 → 槽名」，就是为了解决"块和槽不同名"的显示）。它是快照，
不是引用。所以跟随规则**只对它写**。

结论：不要到处撒"改名后通知谁"的钩子，先把副本找出来。找出来之后
同步代码只有十一行。

## 三、跟随规则：判据是"还穿着旧名字"

```cpp
const auto previous = slot->name;
rack.setSlotName (slotId, newName);
if (slot->name == previous) return;          // 模型没真改（空名/同名），别动块

bool followed = false;
for (每个层的每个块)
    if (sample.outputSlotId == slotId && sample.name == previous) {
        sample.name = slot->name;
        followed = true;
    }
if (followed) stack.notifyNotesChanged();
```

判据是 `sample.name == previous`，不是 `sample.outputSlotId == slotId`。

只按挂载判的话，用户给某一块单独起过名（"我的拍子"），改槽名会把它抹掉——
那是用户自己说的话，不该被系统的默认行为覆盖。而"还穿着旧名字"这个条件，
恰好就是"这块没被单独命名过"的可观测形式：不用加 `isAutoNamed` 标志位，
不用改工程文件格式。

反向也成立：把块名改成和槽名一样之后，用户再改槽名，它会跟着走——因为它现在
又长成槽名的样子了。这不是 bug，这是"没有独立名字"的另一种到达方式。

## 四、`namesChanged()` 必须和 `layersChanged()` 分开

P73 定下 `layersChanged()` **无条件**关掉编辑中的组：撤销/加载会把同一个组 id
带回来，存在性检查会答 yes，所以只能无条件清。

但"站在组里给这个组改名"是常态用法。改名转发 `layersChanged()` 的话，
用户双击组名、敲完回车，人就从这个组里被踢出去了。自检里那条
`-1（应为 497）` 就是它。

于是 `Listener::namesChanged()` 单独开一个虚函数，默认实现转发 `layersChanged()`
（其它监听者不关心区别），只有 `PianoRollComponent` override 成纯 `repaint()`：

```cpp
void PianoRollComponent::namesChanged() { repaint(); }
```

模型里三个 setName 只在**名字真的变了**的时候发通知，所以"改名字"在撤销历史里
正好是一步。

## 五、记 id，不记行号

三个面板的 `renamingLayerId` / `renamingSlotId` / (`renamingLayerId`,`renamingGroupId`)
全是 id。原因是框开着的时候用户能干别的事：删层、删卡、拖重排。索引会指向别人，
id 不会。自愈逻辑因此是"这个 id 还在不在"，不是"第几行还有没有东西"：

- 层被删 → `close(false)`

# Phase 80 — 工程速度可以自动化

## 一、要的那句话，和它牵出来的东西

> 「要可以对工程速度做自动化」

前八条自动化（图层音量/声相、组电平、主输出、槽位六项、音源参数）都是**给某个信号加乘数**：
信号本来就在，曲线只决定它多大。速度不是。速度改的是**时间的刻度**——它决定"一拍有多长"，
而"多长"是所有位置、所有时长、所有导出长度的分母。

于是这句话的真实工作量不在曲线上，在一个 double 上：全工程到处是 `secondsPerBeat`，
`beat * spb` 是"拍→秒"的**唯一**换算方式，它成立的前提就是 spb 是常数。一旦 BPM 会变：

    t(拍 x) = ∫₀ˣ (60 / bpm(u)) du

一个积分，不是一个乘法。任何"用当前 BPM × 拍数"的写法在变速下都是错的（而且错得不明显：
在曲线两端附近看起来几乎对）。**先把这件事做对，再谈曲线怎么画。**

## 二、`TempoMap`：时间是积分

`Source/Model/TempoMap.{h,cpp}`。断点表 `{beat, bpm}` + 预先算好的 `secondsAt[i]`
（每个断点处已走过的秒数）。

段内 BPM 对**拍**线性：`bpm(x) = p0 + q·(x - b0)`，`q = (p1 - p0)/(b1 - b0)`。于是

    t(x) = t0 + ∫₀^dx 60/(p0 + q·u) du = t0 + (60/q)·ln((p0 + q·dx)/p0)

反解（把时间轴上的秒换回拍）先求那一刻的速度：

    bpm(t) = p0 · exp(q·(t - t0)/60)          ← bpm 对秒是指数
    x(t)   = b0 + (bpm(t) - p0)/q

两者互为**精确**反函数，不是两套近似。

平坦段（`|q| < 1e-9`）走线性形式：`span·60/bpm`。这不是优化，是**数值正确性**——
`ln(1+ε)` 在 ε 极小时有效位比直接乘少。反函数同样分两支。

`setPoints()` 是唯一入口，`flat()` 与 `fromLane()` 都经过它：过滤非有限值 → clamp 到
`[0,∞)` 与 `[30,300]` → `stable_sort` → 同 beat 去重（**后者胜**：曲线从那一拍起就是这个速度，
这也是拖一个点压到另一个点上的直觉）→ 空则补 `{0,120}` → 首点 beat > 0 就补一个
`{0, 首点.bpm}`（否则 0 拍之前的音符会落到负秒）→ 重建 `secondsAt`。

首点补齐这一条很容易漏：`beatAtSeconds(0)` 和 `secondsAtBeat(negative)` 在自检里各有一条，
缺了它整条曲线会平移。

## 三、为什么曲线值是 `60·4^v`

`bpm = 60 · 4^v`：v=0 → 60、0.5 → 120、1 → 240。

不是线性 30..300。理由是"一半"这个词：用户把曲线画到行高的一半，期望看到的是**半个速度**，
而 60→120 正好是一个八度、4 的 0.5 次方。线性映射给的是 165 BPM —— 一个谁也没画过的数。

`tempo::bpmForValue` / `valueForBpm` 是一对，且在 `TempoMap.h` 里，不在 UI 里：
工程文件存的是**曲线值**（0..1），BPM 是它的解释，解释只能有一份。

## 四、`TempoModel` 为什么不进 `MixerModel`

速度不属于混音台，而且 `MixerModel::resetToDefault()` 是"重置混音台"这个动作的实现。
把速度图挂在里面，用户点一次"重置混音台"就顺手把他画的速度曲线抹了。

所以新开 `Model/TempoModel`：一条 lane + `Listener::tempoChanged()`。工程文件里
`<TempoAutomation>` 也相应地是 **root 的子元素**，与 `<Mixer>` 平级，而不是它的子节点。

`resetToDefault(len)` 用 `valueForBpm(120)` 而不是 lane 构造时的 1.0：lane 的默认值是满量程 1.0
（对音量来说是"不变"），对速度来说 1.0 是 240 BPM —— "打开速度自动化"这一步就把工程翻了一倍。

`AutomationOwner::tempo` 是新的 owner，`ownerId`/`target` 恒为 0。`addTrack` 里原本
`owner != master && ownerId <= 0` 就拒，现在为 tempo 也开一口 —— 不这么做，行加不进去，
而失败是静默的（返回 -1）。

## 五、把 `secondsPerBeat` 拿掉

| 位置 | 原来是 | 现在是 |
|---|---|---|
| `PublishedSchedule` | `double secondsPerBeat` | `TempoMap tempo` |
| `lengthSeconds()` | `lengthBeats * spb` | `tempo.secondsAtBeat(lengthBeats)` |
| 音符起奏 | `startBeat * spb` | `tempo.secondsAtBeat(startBeat)` |
| 采样块时长 | `len * spb` | `tempo.secondsBetween(start, end)` |
| `getPosition()` | `samples / sr` 反乘 | `tempo.beatAtSeconds(...)` |
| `setPosition()` | `beat * spb` | `tempo.beatAtSeconds(...)` |
| `renderNextBlock` | 块首算一次 `beatsPerSample` | **每段重算** |
| 导出/渲染长度 | `contentBeats * spb` | `tempo.secondsAtBeat(contentBeats)` |

**"每段重算"是这一节唯一的性能—正确性取舍。** 一块 512 帧在 120 BPM 下是 0.011 秒，
在渐快曲线下块内速度变化很小，每块算一次看着够用；但自检显示推一秒音频，
只按块首速度算会漂到 0.95586 秒（差 4.4e-2），按 512 帧一段重算是 3.8e-3。
后者的成本是一次 `secondsPerBeatAt`（短扫描 + 一次 log/exp），可以忽略。

`PublishedSchedule` 里放的是 `TempoMap` **值**：消息线程算好，随 schedule 一起发布。
音频线程不构建图、不分配、不加锁。

- 勾选态不自己记：`automationTracksChanged()` 里
  `bpmField.setTempoAutomationShown(hasTempoAutomationTrack())` 反灌。

# Phase 81 — 录制：一次按键，两样产物

## 一、用户要的那句话

> 「增加录制音频采样和 midi 的功能，midi 录制进去之后，音符自动编组，然后把录进去的自动化曲线写进编组的自动化里」

拆成四条：① 能录音频采样；② 能录 MIDI；③ 录进去的音符**自动编组**；④ 录制期间的自动化曲线
写进**那个组**的 lane。动手前用 `AskUserQuestion` 确认了两个分叉：

- 录进来的音频落到哪 → **当前图层 + 采样块**（不新建层，不新建工程级"录音轨"）
- "录进去的自动化曲线"取哪一路 → **MIDI CC → 组音量/声相**（不是画笔画出来的、也不是插件参数扫）

## 二、第一件事不是界面，是引擎从来没向系统要过输入

`AudioEngine::start()` 从 P1 起就是：

```cpp
lastError = deviceManager.initialise (0, 2, nullptr, true);
```

两个参数是**输入/输出通道数**。`0` 意味着 `inputChannelData` 永远是空指针——录音这件事在引擎里
根本没有入口，跟界面上有没有按钮无关。改成 `(2, 2)`，失败回落 `(0, 2)`（没有输入设备的机器
也必须能开引擎，否则播放都起不来）。

这一步之后 `beginRecording()` 才有意义：

```cpp
const bool hasInput = deviceManager.getCurrentAudioDevice() != nullptr
                      && deviceManager.getCurrentAudioDevice()->getActiveInputChannels().countNumberOfSetBits() > 0;
```

**没有输入的机器上，MIDI 录制仍然要能用**——所以 `beginRecording()` 返回 false 只表示"音频这条路
不通"，`takeCollector.begin()` 与 `recording.store(true)` 照旧。这是"两样产物"结构最早兑现的一次红利：
一条路断了不影响另一条。

## 三、线程边界：拍号随事件过桥

这是本阶段最容易写错的地方，而且写错了不会崩、只会**整体往后飘**。

`MidiInputHub::onNote` / `onControl` 跑在 **MIDI 线程**；`TakeCollector` 持有 `std::vector<RecordedNote>`，
只能在消息线程动。所以事件必须过桥——但**拍号不能在过桥之后取**：

```cpp
// 消息线程里问位置 = 把 callAsync 的队列延迟算成走音
juce::MessageManager::callAsync ([this, pitch, velocity, on]
{ recordNoteAt (pitch, velocity, on, audio.getPlayback().getPositionBeats()); });
```

正确写法（`MainComponent.cpp`，`onNote` 与 `onControl` 两处同形）：

```cpp
if (recording.load (std::memory_order_relaxed))
{
    const double beatNow = audio.getPlayback().getPositionBeats();   // 就在 MIDI 线程读
    juce::MessageManager::callAsync ([this, pitch, velocity, on, beatNow]
    { if (recording.load()) recordNoteAt (pitch, velocity, on, beatNow); });
}
```

两条前置条件：`PlaybackEngine::getPositionBeats()` 返回的是 `std::atomic<double>`（relaxed），
MIDI 线程读它安全；`recording` 也必须是 `std::atomic<bool>`，因为 MIDI 线程要读。
lambda 里再查一次 `recording`，是因为排队期间用户可能已经按了停止——**过桥之后世界会变**。

## 四、两样产物，两个落点

录音不是一个功能，是两件：

| 录到了什么 | 它是什么东西 | 落到哪 |
|---|---|---|
| 声卡听到了什么 | 一段时间 | `makeSampleBuffer` → `writeSampleFile`（WAV）→ 采样器槽 + 当前图层的采样块 |
| 手弹了什么 | 音符 | 新建「录音 N」编组，`assignNotesToGroup` |
| 手拧了什么 | 手 | 那个组的 `level` / `pan` lane |

硬把前两样塞进同一个对象（"录音事件"）会让后面每一处都要分叉：块要能拉伸、音符要能改音高，
它们的编辑手势完全不同。

`commitTake(take, audioTake, sampleRate)` 是唯一落位入口（按钮与自检共用），顺序是：

1. 空 take 直接 `return -1`，**不 bump 编号**（否则一串空按会留下「录音 7」这种空组）
2. `++recordingCounter`，后面的音频块和组共用这个号
3. 音频：`clip.outputSlotId = rack.addSampler (buffer, clip.path, clip.name)`，再 `layer->addSample`
4. 音符：`layer->addGroup (utf8 ("录音 ") + String (counter), groupPalette::nextGroupColour (…))`
   → `assignNotesToGroup (noteIds, groupId, 0)` → `applyRecordedControls (*group, take)`

**块宽走 `TempoMap`**：

```cpp
const double endOfTake = playback.beatAtSeconds (playback.secondsAtBeat (clip.startBeat)
                                                 + buffer->lengthSeconds());
clip.lengthBeats = juce::jmax (1.0, endOfTake - clip.startBeat);
```

P80 之后全工程都不该再出现 `秒 × BPM / 60`——渐快段里那个乘法每条都不对。

WAV 是手写的（44 字节头 + 16-bit PCM，`SampleLibrary::writeSampleFile`）：JUCE 的
`WavAudioFormat` 也能写，但落盘这件事的价值在于"能被别的软件打开"，而头里那几个字段
（chunk size、byte rate、block align）自己写一遍比记住 `AudioFormatWriter` 的生存期规则更便宜。

## 五、CC 只认三条，其余不猜

```cpp
RecordTarget recordTargetFor (int controller) noexcept
{
    if (controller == 7 || controller == 11)     // channel volume / expression
        return RecordTarget::level;
    if (controller == 10)                        // pan
        return RecordTarget::pan;
    return RecordTarget::none;
}
```

其余 CC（调制轮、延音踏板、aftertouch…）计入 `Take::ignoredControls` 并**丢弃**。没有文档的映射
就是编的：把 CC 1 猜成"音量"会在用户下一次弹琴时静默地改掉组音量。`ignoredControls` 存在的
意义是让"我明明推了它却没录上"有一个可查的数字，而不是让它去猜第二条。

`Take::getNumControlsFor (target)` 用于"这条曲线到底有没有内容"的判断——不是看 `controls`
非空就写两条 lane。

## 六、曲线进 lane 之前必须稀疏化

`AutomationLane::maxPoints = 32`。一次推子推下来两百个 CC。直接写的话 `loadPoints` 会截断到
最后 32 个点——曲线变成"最后那一小段"，前面的形状全丢。

`decimateRecordedCurve` 两趟漏斗：

1. 顺序扫，**值动超过 `controlValueStep`（1%）或距上一点超过 `controlTimeStep`（0.5 拍）**才留点
   ——前者保住"手在抖"的形状，后者保住"慢慢扫过去"的形状。只看前者会把慢速扫弦削成两个点。
2. 若还超上限，等距抽到 30（`maxRecordedCurvePoints`），**首尾钉住**。

然后：

```cpp
if (points.size() < 2) continue;    // 少于两点不写 lane
```

因为 `loadPoints` 会把单点修成**横贯全工程的直线**——推子只动一次，用户的组音量就被钉到工程末尾。
（P81-H）

## 七、入口：Stop 右边那颗红点

`getRecordButtonBounds()` = `getStopButtonBounds().getRight() + 6px`，30×28，画法沿用
`drawButtonPlate` + 中间的圆点（录音中是实心 `theme::record`，否则 62% 透明，hover 85%）。

`toggleRecording` → `startRecording` / `finishRecording`。`startRecording` 里："没在播就先播"——
录音必须有走带在走，否则所有音符都落在同一拍。`finishRecording` 里顺序固定：

```cpp
recording.store (false);                                  // 先关闸，MIDI 线程不再往里塞
const Take take = takeCollector.finish (endBeat);
commitTake (take, audio.endRecording(), audio.getRecordSampleRate());
```

**停止键要先收尾再归位**：`stopTransport()` 里 `finishRecording()` 必须在
`parkTransportAt (stopDecision (…).beat)` **之前**——反过来的话 `endBeat` 读的是已经跳回起点的位置，
录到的东西全被算成零长度。（P81-G 是这条的自检侧教训）

## 十、坑

P81-A（`initialise (0, 2, …)` 从没要过输入）、P81-B（消息线程里问走带位置）、
P81-C（`finish()` 先 disarm 再读 `writePos`）、P81-D（`AudioBuffer (2, 24000)` 是 0.5 秒）、
P81-E（demo 音高在视野外且被组框压住）、P81-F（相对路径的基准是 cwd，WAV 落进仓库）、
P81-G（走带停着时 `stopTransport()` 是空操作）、P81-H（单点曲线会被撑成横线）、
P81-I（断言的消息参数无条件求值 → 崩溃而非报红）、P81-J（`ramp` 遮蔽 `ramp`，零 warning 造假）。

P81-A 与 P81-I 是这一阶段最贵的两条：前者说明"功能缺的是引擎，不是界面"，
后者说明"断言要先能报，再谈判对错"。

## 十一、边界

- **一次按键只产出一个组**：分两次录同一段会得到两个「录音 N」，没有"接着上一组继续录"。
- **录进来的音频不切分**：一次按到底就是一个块，不按静音段自动分段，也没有实时波形与录音头
  （画布上只有那颗红点变亮）。
- **CC 只映射三条**（7/11→level、10→pan），其余记账不猜；`Take::ignoredControls` 是唯一能查的地方。
- **`RecordBuffer` 满了自己停**（默认 300 秒），界面无提示；停下时还按着的音符会正常收尾。
- **采样率跟随设备**（48 kHz），不与工程帧对齐；WAV 是 16-bit PCM，写死 44 字节头。
- **录音不进撤销之外的任何历史**：撤销仍然是整工程 XML 快照（P71），一次 take 是一次手势。
- **`formatVersion` 仍是 25**：录音产出用的全是已有字段，没有新的落盘状态。
