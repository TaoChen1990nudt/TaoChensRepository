## Phase 56：多选拉伸、组粘贴、复制到后一小节

### 需求
1. 多个采样选中时，拖长度要一起改。
2. 组的复制粘贴，粘贴出来必须是组，不是散开的组内容。
3. 组的右键菜单要有「复制到后一小节」。

### 实现
- **多选拉伸**：`applySampleTrimDrag(主块, 目标, 边, 兄弟原件)`。先按 P29 的规则摆主块，
  再把**实际 delta** 读回来给兄弟（尾 `length += delta`，头 `start += delta` 且终点钉住）。
  兄弟各走同一个 `applySampleTrim`，各自的 offset 与最小长度照旧生效。
  `dragTrimOriginals` 在 mouseDown 抓住选中块的边时捕获；`simulateSampleTrim` 走同一条路。
- **组粘贴**：`isWholeGroupSelected(groupId, includeSamples = false)`（挂载不看块、复制要看块）；
  `copyNotesToClipboard` 认整组时把块一并放进 `sampleClip`（不再依赖调用方追加第二次 pass）；
  `pasteEditClipboard` 见 `groupClip.valid` 直接走 `pasteGroupFromClipboard()`：一个锚点、
  一次建组、音符与块都写 `newGroupId`。抽出 `captureGroupClip` / `addGroupCopy` /
  `insertGroupMembers`，`duplicateGroupToNextBar` 复用同一套。
  `cutNotesToClipboard` 补：整组剪切时把块也从时间线删掉（否则剪切→粘贴会复制一份没搬走的音频）。
- **复制到后一小节**：`duplicateGroupToNextBar(layerIndex, groupId)`，模型级克隆，不动剪贴板。
  目标 `nextBarLineAfter(起点)`；若仍压源上则 `barLineAtOrAfter(源结束)`。菜单项 id 8，
  放在「选中整组」下面。菜单构造抽成 `fillGroupMenu(menu, ...)` 供自检读（showMenuAsync 无法在
  headless 里观察）。
- `SharedRules.h` 新增 `beatsPerBar` / `nextBarLineAfter` / `barLineAtOrAfter`，标尺不再写字面量。

## Phase 57：组框贴住成员、粘贴复用源组

### 需求
1. 组的边框与采样的边框之间不要留距离。
2. 组粘贴之后不要重新新建一个组，而是复用被粘贴的组。

### 实现
- **组框零外扩**：`groupFrameOf()` 返回 `getGroupContentBounds()` 本身（去掉 `expanded(3px)`）。
  3px 原本是"组线画在成员之下、不外扩就被块的填充吃掉"的补丁；现在把描边拆到成员**之上**
  单独画（新函数 `drawGroupFrames`，插在 `drawNotes` 之后），填充仍留在 `drawGroupBands`。
  描边向内容框内缩半个线宽，正好压在块自己那圈边框上。
  绘制、命中（`getGroupFrameAt`）、自检都调 `groupFrameOf` —— 画的和测的是同一个函数。
- **粘贴复用组**：`GroupClip` 新增 `sourceGroupId`（`captureGroupClip` 写入）。
  `pasteGroupFromClipboard()` 先看 `active->findGroup(sourceGroupId)`：
  在 → 直接往里加成员（同一 name/colour/mount/trim/曲线）；不在（剪切榨干、跨图层）→
  `addGroupCopy` 建一个同名同色的新组。清理改成 `if (! reused) removeGroup(...)`。
- **统一粘贴入口**：`pasteNotesFromClipboard()` 开头见 `groupClip.valid` 就转发给
  `pasteGroupFromClipboard()`，否则旧入口会以"散音符"身份粘一遍、块留在剪贴板上。
  `duplicateGroupToNextBar()` 仍新建组（那是"再来一份"）。

1. `groupFrameOf` 恢复 `expanded(3px)` → 零间隙断言 FAIL（frame 103.8 / block 96）。
2. `reused = false`（恒新建组）→ 三条粘贴断言 FAIL（1→2 组、组内 3 音符等）。
3. 删掉旧入口的转发 → "组内现 4 音符 / 1 采样"、"粘贴后选区 2 notes / 0 clips" FAIL。

### 结果

## Phase 58 — 组 = 一个定义 + 多次出现

用户五条，全部指向同一处模型的缺口：P57 让"粘贴"把副本**借给源组**，于是副本和源共用一个
括号——"拖动长度有时失败"是另一件事，但"粘到了组的内部""复用对象之间移动不独立"是它的必然。

### 模型
`NoteGroup` 从此只是**定义**；时间线上的每一份是它的一次**出现**。
- `NoteEvent` / `SampleEvent` 各加 `int groupOccurrence = 0`（默认 0 = 老工程 = 第 0 次出现）。
- 新 API：`assignNotes/SamplesToGroup(ids, gid, occurrence = 0)`、`getGroupOccurrences(gid)`
  （派生、升序）、`nextGroupOccurrence(gid)`、`getOccurrenceNoteIds/SampleIds`、
  `countNotes/SamplesInOccurrence`、`getGroupOccurrenceOfNote/Sample`。
- `removeGroup` / 悬空组修复同时把 occurrence 归 0。
- 约定：**`occurrence < 0` = 该组所有出现**，`>= 0` = 只那一次。所有新参数的默认值都取这个，
  所以老调用点行为不变。
- `formatVersion` 23 → 24：`<Note>` / `<Sample>` 增 `groupocc`，只在非 0 时写。

### 五条需求各落在哪
1. **选中采样后拖长度有时失败** → 根因是拾取顺序。`hitTestSample` 改成**倒序**（最上层优先），
   mouseDown 块分支加"已选块的边缘优先"：`selectedTrimEdgeAt(pos)` 命中就以它为准，
   且**不改写选区**；`mouseMove` 同步显示左右箭头光标。拖动时 `grabbedId` 用它。
2. **播放头回到原处时滚动条要复原** → `setScrollBeats` / `setBeatWidthAround` 末尾
   `noteUserScroll()` 记住用户视野；`setPlayheadBeat` 开头先判断播放头是否落回该视野，
   是就滚回去并停止跟随。跟随不再是单向的。
3. **粘贴组粘到了组内部** → `pasteGroupFromClipboard()` 仍复用源 `NoteGroup`，但用
   `nextGroupOccurrence()` 生成新出现号，`insertGroupMembers(..., occurrence, ...)` 写进去。
4. **编组栏的组拖到钢琴窗 = 放一处** → `atomic-group:<层>:<组>` payload；
   `GroupPanel` 的 body 按下只 arm，超 4px `startDragging`，折叠延后到 `mouseUp`；
   落点唯一实现 `PianoRollComponent::placeGroupAppearance()`（模板 = 该组最早一次出现），
   预览画落点竖线 + 虚线跨度幽灵 + 标签「放一处 <组名>」。
5. **各出现独立移动** → 拖动/复制/解散/框/标签/自检全部按次：`getGroupContentBounds`、
   `captureGroupClips`、`armGroupMove`、`simulateGroupMove`、`duplicateGroupToNextBar`、
   `disbandGroup`（该组还有别处时只解这一次，只剩这一处才 `removeGroup`）、
   `drawGroupBands/Frames/Labels`（双层循环，每处一个括号一个标签）、`getGroupBeatSpan`、
   `isWholeGroupSelected`、`selectGroup`、新增 `getSelectedGroupOccurrence`。
   引擎侧：`ScheduledNote/ScheduledClip.groupOccurrence`、`Scope.groupOccurrence`
   （-1 = 所有出现），所以"只渲染这一处"能选。

## Phase 59 — 拉伸拾取收进块内、编组栏镜像、折叠行只留组名

三条都小，但第一条是"看着像功能缺失、其实是量纲/范围写错"的典型。

### 1. 选中多个采样拖动长度，只有最右边那块有效
根因：`selectedTrimEdgeAt` 的 band 判定只有一半。
- `x >= right - band` 没配 `x <= right` → 对块**右边一切像素**成立；
- `x <= left + band` 没配 `x >= left` → 对块**左边一切像素**成立。
选中 A/B/C 三块相邻，按 B 的尾巴：倒序遍历先问 C，`x <= C.left + band` 命中 → 返回"C 的头"。
拖 C 的头 = 移动 `sourceOffsetSeconds`，已贴底 → `jlimit` 夹住 → delta = 0 → 什么都不动。
用户看到"按了没反应"，而且只有最右那块的头没有右邻居、尾没有遮拦，所以"只有它能拖"。
修法两层：①要求指针在块内（x 与 y 都在）；②命中后按**距离最近**的边定 tail/head，
并用倒序遍历 + 严格小于让最上层赢平局（A.right 与 B.left 是同一个像素）。
自检走 `getBlockGrabAtForTest`（拾取的唯一顺序），再加一条端到端：
抓中块尾巴 → `simulateSampleTrim` → 三块按**同一个 delta** 变短（0.946 / 0.946 / 0.946）。

### 2. 组在钢琴窗选中时，编组栏那行要高亮
新增 `PianoRollComponent::getSelectedGroups()`（派生，不存 flag）：每个组的每个出现问一次
`isWholeGroupSelected(gid, true, occ)`，任一出现整体入选即算。主窗体在 `onSelectionChanged`
里用 `syncGroupPanelSelection()` 推给 `GroupPanel::setSelectedGroups(rows)`，面板按
`(layerIndex, groupId)` 比较（组在 vector 里，指针会失效）。
绘制用组色 15% 填充 + 60% 描边；**左竖条留给"喂给聚光灯音源"**那个已有标记，两者可同时出现。

### 3. 折叠之后的组名背后有字

（`x=46, w=width-106, y+4, h=18`）。直接删掉那段：折叠 = 一行，那行是标题。

## Phase 61 — 缩放视口：不够就加长、多了就还回去（同一档）

### 现象
把钢琴窗缩到很宽（Ctrl+滚轮往左、拖标尺）时，视口宽度越过标尺长度的**那一档**不加长，
下一档才加长；中间那一段右边是一条没有网格、没有小节线的死带。缩回去时反倒正常。

### 根因（PITFALLS P61-A）
`clampScroll()` 里：`if (scrollBeats + visibleBeats > timelineBeats) ensureTimelineExtendsTo (...)`。
缩放以某一拍为锚，锚点常在 beat 0 左边，`scrollBeats` 在这里是**负数**，两行之后才被
`jlimit(0, maxBeats, …)` 夹回 0。用负数求和把需求算小了：`-16.6 + 74.5 = 57.9 < 64`，
于是"64 够长"；而真正要显示的是 `[0, 74.5]`。

### 修法
```cpp
const double wanted = juce::jmax (0.0, scrollBeats) + visibleBeats;
if (wanted > timelineBeats) ensureTimelineExtendsTo (wanted);
```
顺序固定为「夹下界 → 问需求 → 夹上界 → 回收」，不新增入口：
缩放的 `setBeatWidthAround()` 本来就调 `clampScroll()`，加长与回收都在那一处结算。
回收不用另写——`visible` 变小后 `trimTimelineToView()` 自然把长度落回 `beatChunk` 的整数倍，
滑块宽度跟着恢复。

### 实测
- 每一档都满足 `visible <= timelineBeats`：`41.4视/64长 → 74.52视/128长 → 92视/128长`（旧：`74.52视/64长`）。
- 缩回去：`128 -> 64 beats`，滑块宽 `394.594 -> 394.594`（完全回到原位）。

### 自检（+2：543 → 545）
1. "Zooming out lengthens the roll on the same notch, not the next one" —— 8 档逐档检查
   `visible <= timelineBeats`，并记录每档数字；只查最后一档会漏掉"差一档"。
2. "Zooming back in gives the extra ruler back, thumb included" —— 长度与滑块宽度同时回到基准。

### 咬测（2 处，全部先 FAIL 后还原）
1. `wanted` 去掉 `jmax(0.0, …)` → `74.52视/64长`，正中死带现象。
2. `clampScroll()` 末尾不调 `trimTimelineToView()` → 缩放后 `128 -> 128`、滑块 `394.594 -> 197.297`。

### 结果
编译零 error 零 warning；**545 PASS / 0 FAIL / EXIT=0**；`formatVersion` 仍是 24，工程文件格式未动。
探针（临时 fopen 调试输出 + 临时 check）已全部清除，`grep -c "DBG \|p61dbg"` 为 0。

P58 让组 = 定义 + 多次出现，但"定义"里只有 name/颜色/挂载/trim/曲线；**成员内容是各存一份的**，
所以两处出现可以长得不一样——这正是需求 1 的缺口。

P62 把语义补成：**出现只拥有位置，其余都是组的。**
- `NoteGroup::occurrenceStarts`（`map<int,double>`）：每次出现的起始拍。
  **必须存**：只按"最早成员"推导的话，删掉那个成员位置就会跟着走，之后每次同步把这一处拖一次。
  `Layer::occurrenceStart()` 第一次被问到时物化并写回，此后只在**整处移动**时改（`setOccurrenceStart`）。
- `Layer::syncGroupShape(gid, source)`：按成员序 `(start, pitch, id)` 配对，
  把源出现的"相对起点 + 全部属性"写进每个兄弟出现，锚点用兄弟自己的起点。多退少补，
  相同则一个字节都不改（`sameNoteShape` / `sameClipShape`），所以整处拖动时它是零开销的空转。
- `Layer::collectTwinMembers(notes, clips, twinNotes, twinClips)`：**离开形状**没有模板可抄，
  在原件还在时按序号配对，返回兄弟出现里的对应成员。

- 整处拖动、整处删除 = **对这一份副本的决定**，兄弟不动。

## Phase 64：播放头越过窗口 3/4 时钢琴窗闪屏

用户：「当播放头播放到标尺右边某个位置时，会发生钢琴窗闪屏的 bug」。

### 探针先量

临时加了三个计数器（`probeFollowFrames` / `probeFollowStuck` / `probeBandFrames`），
220 拍、每帧 0.033 拍跑一遍：

```
默认 16px/拍：可见 69 拍 · 整窗重绘 265 帧 · 滚动跳变 526 次，最大 58.7 拍
放大 64px/拍：可见 17.2 拍 · 整窗重绘 86 帧 · 滚动跳变 152 次
缩小  6px/拍：可见 92 拍 · 整窗重绘 351 帧 · 滚动跳变 699 次
```

把每次跳变的前 6 条打出来，一眼就看见来回：

```
[51.8:+41.4] [51.8:-41.4] [51.8:+41.5] [51.9:-41.5] [51.9:+41.6] [51.9:-41.6]
```

### 根因

`setPlayheadBeat()` 的两条分支判据重叠：

1. 推走（播放头越过 `scrollBeats + visible*0.75`）时，把当时的 `scrollBeats` 记进
   `userScrollBeats`，再把视图前移 60% 窗口。**被记下的那个窗口本来就含当前播放头。**
2. 归还（播放头落在 `[userScrollBeats, userScrollBeats + visible]` 内）于是下一帧立刻成立，
   视图退回原处；再下一帧播放头仍在 75% 之外，又推走……

60fps 无限来回，每次 60% 窗口宽。用户说的"标尺右边某个位置"就是 75% 那条触发线。

### 修法

归还加一条：**播放头必须在往回走**。

```cpp
if (followScrolled && visible > 1.0
     && beats < previous - 1.0e-9          // ← P64
     && beats >= userScrollBeats - 1.0e-9
     && beats <= userScrollBeats + visible + 1.0e-9)
```

前进的播放永不归还；loop 跳回 / scrub / seek 都是回退，归还照旧（P58 语义不变）。

### 结果

修完：默认缩放 220 拍里 **5 次跟随、每次 +41.4 拍、回退 0 次**（原来 526 次跳变、265 帧整窗重绘）。

### 自检

新增两条（`SelfTest.cpp`，Phase 64 段）：

   `backwards == 0 && jumps < 40`，detail 打「15 次跟随，回退 0 次，最大 13.8 拍（窗口 23.0 拍）」。

**559 ALL PASSED / 0 FAIL / EXIT=0**，零 error 零 warning。

## Phase 66：组标签不越界 + 播放跟随改成贴边滑

两条需求：

1. 「组的宽度比组的标题栏窄的时候，标题栏要与组一样宽」
2. 「播放头移出钢琴窗视口左边界时（排除移到 0 点的情况），视口要向左移以保持播放头始终在标尺头部；
   同理移出右边界时向右移，保持播放头始终在标尺尾部」

### 1. 名字标签

`getGroupLabelBounds()` 的宽度只夹在 `[34, 168]` px，且只按文字长度算。一个 0.1 拍的组在屏幕上
是 **5 px**（`getNoteBounds` 的 5 px 下限），标签 34 px 起步 —— 横出组框，压到右边隔壁的内容上。

改：文字宽度再和组框宽度取 `jmin`。

派生问题：`getGroupAutomationHandleBounds()` 是 `pill.getRight() - 12 - 1.5` 写死的，标签 5 px 时
把手在标签**左边外面**，绘制代码照样画（12 px 按钮 + chevron）。加闸：宽 < `12 + 6` 返回空矩形，
绘制处 `if (! handle.isEmpty())`。命中不用改（空矩形 contains 恒 false）。

自检 3 条：窄组标签 5.0 vs 组 5.0；宽组 74.5 vs 190.5（证明不是一律压扁）；窄组无把手、宽组有。

### 2. 播放跟随

旧行为是**翻页**：播放头到窗口 3/4 推走，落到 15%，一次挪 60% 窗口后静止。用户要的是**贴边滑**：
播放头走到右边界就钉在那儿，画面在它下面连续滑；回退同理钉在左边界。

```cpp
const double rightEdge = scrollBeats + visible;
const bool   pastRight = beats > rightEdge + 1.0e-9;
const bool   pastLeft  = beats > 1.0e-9 && beats < scrollBeats - 1.0e-9;
...
const double target = juce::jlimit (0.0, maxBeats, pastRight ? beats - visible : beats);
```

`pastLeft` 的 `beats > 1.0e-9` 就是用户说的「排除移到 0 点」：归零是"回家"，归上面那条
`beats < previous` 的归还分支管；跟着 0 点跑会把用户正在看的窗口拽到开头。

P64 的横跳防护原样保留（归还仍要求回退），所以贴边式不会有"推走—归还"循环。

以前标尺左键拖动只做一件事：`beatAtScreenX(指针 x)` → locate。指针出了网格边界，
映射出来的拍还在长，画面不动，于是播放头跑到窗口外面看不见了。拖到远一点的小节 =
松手、滚轮、再拖，重复几次。

## 实现

新增 `scrubRulerTo (float screenX)`，mouseDown 的点击与 mouseDrag 的拖动都走它
（点击和拖动不可能对不上）。顺序是这件事的全部内容：

```cpp
const double raw = beatAtScreenX (screenX);

if (raw > timelineBeats)                 // 1. 先扩：拖动就是"要更长的标尺"
    ensureTimelineExtendsTo (raw);

const double beat = juce::jlimit (0.0, timelineBeats,
                                  snapEnabled ? snapBeat (raw) : raw);   // 2. 再吸附+夹

if (visible > 1.0)
{
    const double rightEdge = scrollBeats + visible;

    if (beat > rightEdge + 1.0e-9)       // 3. 滚：把播放头钉在被推的那条边
        setScrollBeats (beat - visible);
    else if (beat < scrollBeats - 1.0e-9)
        setScrollBeats (beat);
}

if (onLocateRequested != nullptr)        // 4. 最后才 locate
    onLocateRequested (beat);
```

两条滚动分支和 P66 的贴边跟随是同一个式子（`beats - visible` / `beats`），所以拖出去的
播放头恰好停在标尺尾/头部，而不是"差不多在边上"。

**为什么用吸附后的 `beat` 判滚动，而不是指针的 `raw`**：开着吸附时用户盯着的是播放头。
用 raw 判、用 beat 落，播放头会离边缘半格（6 px），看起来像没贴上去。

## 跟随分支让路

标尺拖拽时 transport 不会停（locate 是 seek 不是 stop），`setPlayheadBeat` 每帧还在进来。
两条跟随分支各加 `dragMode != DragMode::rulerScrub`：**按住期间窗口归拖拽所有**。

# Phase 68 — 网格随缩放退档，吸附跟着走

用户原话：「当缩放范围越来越大时，网格会愈来愈细密，这个时候当网格的间距小于一定值时就略去
中间的网格线，把吸附靠在主要网格上」。

原来的网格只有一档：`gridDivision = 0.25`（1/16），绘制和吸附都写死它。最小缩放
（`minBeatWidth = 12`）时 1/16 之间只有 3 px —— 一片灰，同时吸附还在要求 3 px 一格的精度。

## 实现

```cpp
double PianoRollComponent::visibleGridStep() const noexcept
{
    const double minPixels = (double) ui::pf (5.0f);
    double step = gridDivision;

    while (step * (double) beatWidth < minPixels && step < gridDivision * 1024.0)
        step *= 4.0;            // 1/16 → 拍 → 小节 → 4 小节

    return step;
}
```

三处共用同一个 step：

1. `collectGridLines(from, to, out)` 产出这一屏要画的线（beat 列表）。
2. `drawGridLines` / `drawGridInside` 遍历它上色——"略去中间的线"变成几何的性质，
   画笔里没有第二个步长可以写错。
3. `snapBeat()` 也读它。

**线条等级改为按 beat 判**（`gridLineAlpha(beat)`）：

```cpp
if (onUnit (beat, beatsPerBar)) 0.16f    // 小节
else if (onUnit (beat, 1.0))    0.075f   // 拍
else                            0.030f   // 细分
```

旧代码是 `step % 16` / `step % 4`。步长升到 1 拍后，第 4 拍是 `4 % 16 = 4` → 判成普通拍线，
小节线全丢（P68-A）。

`gridDivision` 保留给"音乐上的最小单位"：音符最短长度、粘贴推进 `snapUp()`、
`nextBarLineAfter(first, gridDivision)`。这些跟"这一屏看得见什么"没关系。

## 自检（580，+5）

| 用例 | 结果 |
|---|---|
| 缩到最小时网格步长升到 1 拍，1/16 的线不再画 | `0.25 / 1.00 拍，33 / 9 根线` |
| 缩到最小时吸附落在拍线上，不落在看不见的 1/16 上 | `2.00 / 6.00` |
| 吸附结果永远是画出来的那根线 | `0 次落在空处` |
| 步长升到一拍后，第 4 拍仍画成小节线 | `0.160 / 0.075 / 0.030` |
| 放大回来后 1/16 的线回来了，吸附也回到 1/16 | `0.25 拍，33 根线，吸附到 2.25` |

钩子：`snapBeatForTest()`、`gridLineAlphaForTest()`；`visibleGridStep()` 与
`collectGridLines()` 直接放 public——前者是 `gridDivision` 的运行时那一半。

## 咬测（3 处，全部先 FAIL 后还原）

1. 阈值改 0（永不退档）→ 2 条挂：`0.25 / 0.25 拍，33 / 33 根线`、`2.25 / 6.00`。
   注意第三条「吸附结果永远是画出来的那根线」**没挂**——两边一起回到旧行为，闭环自洽（P68-B）。
2. `snapBeat` 硬编码 `gridDivision` → 2 条挂：`2.25 / 6.00`、`17 次落在空处`。
3. `beatsPerBar` 换成 `1.0e9`（没有线是小节线）→ 1 条挂：`0.075 / 0.075 / 0.030`。

`580 ALL PASSED / 0 FAIL / EXIT=0`，零 error 零 warning，`grep BITE` 无残留。

## 阈值

`ui::pf (5.0f)` = 6.5 px（scale 1.3）。所以 1/16 在 **beatWidth < 26 px** 时消失
（默认 48 的 54%）。最小档 12 px 时 1 拍 = 12 px，仍然画得开。

第三档（小节、4 小节）在当前 `minBeatWidth = 12` 下够不到，留着是因为阈值是个可调的量，
而循环本来就该把"直到画得开为止"说完，不该写死"最多退一次"。

# Phase 69 — 缩放能放大到 1/64 拍

用户原话：「缩放要能放大到1/64拍」。

P68 把网格的梯子往上接到「小节 / 4 小节」，下限还是 1/16 音符（0.25 拍）。这次把梯子往
**下**接两档，接到 1/64 拍（0.015625）；一并动的有四处：缩放上限、网格档位、吸附、音符最短长度。

## 实现

```cpp
static constexpr float  maxBeatWidth = 768.0f;               // 180 → 768
static constexpr double finestGridStep = gridDivision / 16.0; // 0.015625 拍

double PianoRollComponent::visibleGridStep() const noexcept
{
    const double minPixels = (double) ui::pf (5.0f);
    double step = finestGridStep;          // 从最细一档起，双向 ×4

    while (step * (double) beatWidth < minPixels && step < gridDivision * 1024.0)
        step *= 4.0;

    return step;
}
```

**768 的来历**：最小缩放 12 px 看一个**拍**，最大缩放 12 px 看一个 **1/64 拍**，`12 × 64 = 768`。
两端对称，不是拍脑袋。

**线条等级加第四级**：

```cpp
if (onUnit (beat, beatsPerBar))   return 0.16f;    // 小节
if (onUnit (beat, 1.0))           return 0.075f;   // 拍
if (onUnit (beat, gridDivision))  return 0.030f;   // 1/16 音符（0.25 拍）
return 0.018f;                                     // 1/64 拍那一级
```

四级同亮度就是 P68 要消灭的那片灰。1/64 的线更暗一档，但还看得见（截图放大确认过）。

**最短长度与可见步长分开**：

```cpp
double PianoRollComponent::minimumNoteLength() const noexcept
{
    return juce::jmin (gridDivision, visibleGridStep());   // 只往下让
}
```

`applyNoteResize` 的三处 `gridDivision` 和 `applySampleClipResize` 的 `minLength` 都换成它。
不这么分会出现"网格看得到 1/64、音符缩不到 1/64"。

**档位切换点**：`beatWidth ≥ 416` → 1/64 拍；`104…415` → 1/16 拍；`26…103` → 1/16 音符；
`< 26` → 1 拍（P68 那条）。

## 自检（586，+6）

| 用例 | 结果 |
|---|---|
| 放大到上限时网格细分到 1/64 拍 | `768.0 px/拍，步长 0.01562 拍` |
| 1/64 拍档下 0…1 拍之间画 65 根线 | `65 根线` |
| 放大到 1/64 时吸附落在 1/64 的线上 | `0.29688 / 0.50000` |
| 放大到 1/64 时音符尾巴能缩到 1/64 拍长 | `0.01562 拍` |
| 150 px/拍时网格停在 1/16 拍档 | `0.06250 拍，17 根线` |
| 1/64 的线比 1/16 的线更暗，四级层次都还在 | `0.160 / 0.075 / 0.030 / 0.018` |

钩子：`shrinkNoteTailForTest(noteId, endBeat)` —— 走 `applyNoteResize`，和 `mouseDrag` 同一条路。
只断言 `minimumNoteLength()` 的值等于把常量测两遍。

## 咬测（4 处，全部先 FAIL 后还原）

1. `maxBeatWidth` 留 180 → 4 条挂（`180.0 px/拍，步长 0.06250`）。
2. 步长从 `gridDivision` 起爬 → 5 条挂（`0.25000 拍，5 根线`）。
3. `minimumNoteLength()` 直接返回 `gridDivision` → 1 条挂（`0.25000 拍`）。
4. 1/64 借用 1/16 的 alpha → 1 条挂（`0.030 / 0.030`）。

**第 1 处首版只挂 3 条**：吸附那条写的是 `snapBeatForTest(0.31) → 0.3125`，而 1/64 网格算
`19.84 → 20`、1/16 拍网格算 `4.96 → 5`，**两种网格都给 0.3125**。换成 `0.30` 才分开
（`19.2 → 19` = 0.296875 对 0.3125），记进 PITFALLS 的 P69-B。

`586 ALL PASSED / 0 FAIL / EXIT=0`，零 error 零 warning，`grep BITE` / `grep TEMPZOOM` 无残留。

## 视觉确认

为了看 1/64 那一级到底看不看得见，临时在 `setDemoPlayheadBeats` 里塞了一行
`setBeatWidth(maxBeatWidth)`（标 `TEMPZOOM`），截图后从备份还原并重新编译。

## 边界

  0.0625），那本来就够，说一声我把 `finestGridStep` 抬回 `gridDivision / 4`。

# Phase 71 — 撤销按动作结算 · 钢琴窗预览走图层挂载的音源

用户两条：「把一个音符向右移动 4 拍，如果每一拍是一个状态，就要撤销四次；但鼠标的点击和释放
只是一次动作，所以只该撤销一次」；「钢琴窗预览的 VST 音源音色并不是当前图层挂载的音源音色」。

## 一、撤销的粒度

### 病根：AsyncUpdater 合并的是消息循环，不是动作

```cpp
void MainComponent::modelChanged()
{
    if (restoringHistory) return;
    if (! isUpdatePending()) triggerAsyncUpdate();   // 只挡住同一循环里的连发
}
```

拖拽时每一次 `mouseDrag` 都是一个**新的**消息循环，于是 N 次移动 = N 个快照。注释里那句
"dragging a note fires a notesChanged every mouse move, and each of those is NOT an undo step"
只在"一次回调里既发 layersChanged 又发 notesChanged"这种情形下成立。

### 修法：手势括号 + Desktop 级见证者

```cpp
void beginUndoGesture()
{
    if (undoGestureActive) { endUndoGesture(); return; }   // 上一次没收到 up（窗口关了）
    cancelPendingUpdate();
    commitHistory();          // ← 必须在置标志之前，否则自己也被守卫拦住
    undoGestureActive = true;
}

void endUndoGesture()
{
    if (! undoGestureActive) return;
    undoGestureActive = false;
    cancelPendingUpdate();
    commitHistory();          // 整段手势唯一的一次快照
}

void commitHistory()
{
    if (restoringHistory || history.empty()) return;
    if (undoGestureActive) return;      // 手势中的一切请求都丢掉
    ...
}
```

见证者挂在 **`juce::Desktop`** 上（`addGlobalMouseListener`），不是 `addMouseListener(this, true)`：

- 主窗口子树里的（钢琴窗、时间线、图层栏、机架、编组栏、文件栏、`AutomationWindow`）本来也能覆盖，
- 但 `MixerWindow`、`PluginEditorWindow`、`SettingsWindow`、`ExportDialog` 是**独立顶层窗口**，
  不在那棵树里。推子、插件自己的旋钮都是拖拽，必须一起覆盖。

`undo()` / `redo()` 先 `undoGestureActive = false` 再 `commitHistory()`，于是拖拽中按 Ctrl+Z 的
语义是"把这次拖拽结掉，然后退掉它" = 取消这次拖拽。

### 为什么 JUCE 的顺序正好合用

`juce_Component.cpp::internalMouseUp`：

```cpp
mouseUp (me);                                        // 组件自己的收尾先跑
if (checker.shouldBailOut()) return;
desktop.getMouseListeners().callChecked (...);       // 然后才轮到 listener
MouseListenerList::sendMouseEvent (checker, &MouseListener::mouseUp);
```

`mouseDown` 同序。所以"松手时最后一次写入模型"发生在 `endUndoGesture()` 之前，捕获到的就是
最终状态；`beginUndoGesture()` 在组件 `mouseDown` 之后跑，于是"按下即编辑"（点画板画一个音符）
会被 `begin` 里那次 commit 记录成一步，`end` 时状态相同、不重复落。

`MouseListenerList` 只为**命中的那个组件**发一次（JUCE 的鼠标事件不冒泡到父组件），
所以一次 down / 一次 up，没有重复计数。

## 二、预览的音色

### 病根：预览永远是正弦

```cpp
// renderAudition：不管 slot 是什么
auditionVoice.waveform = Waveform::sine;
if (auto current = getScheduleRaw())
    for (const auto& slot : current->slots)
        if (slot.slotId == slotId) { auditionVoice.waveform = slot.waveform; ... }
```

`slot.waveform` 是**内置合成器**的波形。插件槽的 `pluginId > 0` 在这条路上完全不被看，
所以画音符听到的是"哔"，而播放听到的是 VST —— 同一个音符两种音色。

### 修法：预览 = 现场演奏

引擎里早就有一条专给"真按键"的路（Phase 39 的 live 通道），它已经分派好了插件与振荡器：
`noteOnLive(slotId, pitch, vel)` → fifo → `beginLiveBlock()` → `applyLiveEvent()`
（`slot->pluginId > 0` → `livePluginSlots`，否则 → `liveVoices`）→ `renderLive()`
（`renderLivePlugins()` 把 MIDI 送进 `processBlock`，`renderLiveOscillators()` 画波形）。

预览要做的就是走上这条路：

```cpp
void MainComponent::auditionPreview (int slotId, int pitch, float velocity, bool retrigger)
{
    auto* slot = rack.findSlot (slotId);

    if (slot != nullptr && slot->isPlugin())
    {
        if (! retrigger && hostedPreview.slotId == slotId && hostedPreview.pitch == pitch)
        {   // 同一个手势、同一个音高：续期，不重发（否则插件每像素重触发一次包络）
            hostedPreview.releaseAtMs = now + hostedPreviewHoldMs;
            return;
        }

        releaseHostedPreview();          // 先放开旧音
        audio.getPlayback().stopAudition();  // 掐掉可能还在响的正弦替身
        audio.getPlayback().noteOnLive (slotId, pitch, velocity);

        hostedPreview = { slotId, pitch, now + 420 };
        return;
    }

    releaseHostedPreview();
    audio.getPlayback().auditionNote (pitch, velocity, slotId, retrigger);
}
```

- **谁放的**：`timerCallback()`（60 Hz，在所有 early-out 之前）到点发 `noteOffLive(pitch)`。
  用 `(juce::int32)(now - releaseAtMs) >= 0` 比大小，毫秒计数器 49 天回绕也不会卡住一个音。
- **谁掐的正弦**：`PlaybackEngine::stopAudition()` —— 设标志，`renderAudition()` 把
  `auditionVoice.played` 推到 `kAuditionLength`，走现成的 4 ms 一阶淡出，不在回调里硬切。
  **消费点必须排在 serial 分支之后**：排在前面的话，按住鼠标到第一次渲染之间 `active` 还是
  false，标志被 `exchange` 拿走什么也没做，紧接着 serial 分支把 `played` 归零 → 满音量响 1.1 秒。
- **同步**：`restoreState()` 开头 `releaseHostedPreview()`。会话换了，旧 slot id 可能已经不存在。

### 顺手修：死掉的现场槽位没人回收

`renderLivePlugins()` 原来：

```cpp
if (slot == nullptr || slot->pluginId <= 0) continue;   // 槽位永远留着
auto* plugin = pluginHost->getInstanceWhileLocked (slot->pluginId);
if (plugin == nullptr) continue;
```

`livePluginSlots` 只有 8 格。删一个还在按着的音源、或者把槽改回内置合成器，条目就永久占位，
之后任何按键都不响 —— 而且 `hasLiveNotes()` 也看不出来（那段代码里 `++engaged` 在 continue
之后，engaged 被记成 0）。

新增 `pruneLivePluginSlots(current)`，在 **`renderLive()` 开头**调用，只读 schedule、
**不依赖 pluginHost**：指向的槽不存在、或 `pluginId <= 0`、或已经响完（`numHeld == 0 &&
tailFrames <= 0`）→ 交还格位并重算 `livePluginEngaged`。

## 三、自检（596 → 606）

新增 10 条：

| 断言 | 判据 |
|---|---|
| 拖动途中不落任何撤销步骤 | `getHistorySize()` 在 4 次 move 之后仍等于起点 |
| 一次拖拽（四次更新）只留一个撤销步骤 | 释放后 `+1` |
| 撤销一次就回到拖拽前的位置 | `note->startBeat == fromBeat` |
| 图层挂的是 VST 时，预览交给插件演奏而不是正弦 | `hostedPreview.pitch == 60 && !hasAudition()` |
| 预览换音高时先放开旧音 | `hostedPreview.pitch == 64` |
| 预览结束会放开按住的音 | `pitch == -1 && slotId == -1` |
| 预览的音符真的交给了插件演奏 | `getLivePluginSlotCount() == 1`（在槽还是插件时 drain） |
| 插件预览放下后引擎不再占着现场槽位 | `getLivePluginSlotCount() == 0` |
| 内置合成器的预览仍走振荡器 | `hasAudition()` |
| 停止预览后振荡器会自己收干净 | 20 块 512 之后 `!hasAudition()` |

新加的公开量：`PlaybackEngine::getLivePluginSlotCount()`（八格表里还占着几格）。
没有它，"死槽"这件事在外部完全不可见。

咬测 4 处（全部先 FAIL 后还原）：

1. `commitHistory()` 去掉手势守卫 → 3 条挂：`4 步 / 拖拽中`、`4 步`、撤销后 `3.000`。
2. `auditionPreview()` 不走插件分支 → 2 条挂：`held -1 / 还在发正弦`。
3. `pruneLivePluginSlots()` 清零改成 `continue` → 1 条挂：`1 个槽 / 仍然占着`。
4. `stopAudition` 的处理 `if (false && ...)` → 1 条挂：`还在响`。

第 3 条第一版**没咬住**（P71-C）：断言先写成 `!hasLiveNotes()`，缺陷版把 engaged 记成 0 就过了；
而且测试是在把槽改回内置合成器**之后**才 drain，事件走了振荡器分支，压根没建出槽位。
补 `getLivePluginSlotCount()` + 把 drain 提前到插件还挂着的时候，才真正挂。

## 四、边界与遗留

- **不是所有编辑都过鼠标**：键盘删除、菜单命令、拖放落点走的还是 AsyncUpdater 那一路，
  一次动作落一步，正确。滚轮连滚 N 格仍是 N 步（每格是一次独立动作），未改。
- **双击**：JUCE 在 `mouseUp` 与 listener 之后才调 `mouseDoubleClick`，所以双击里的编辑落在
  手势之外，是独立一步。行为可接受（双击本来就是一次动作）。
- **`beginUndoGesture` / `endUndoGesture` 各做一次完整 XML 序列化**（`captureState()`）。
  只在鼠标按下/释放时发生，几百音符的工程约 1 ms 量级；没有改成"只在 `isUpdatePending()` 时
  commit"，因为漏一次就是漏一步撤销，正确性优先。
- **插件预览每换一个音高就是一次 noteOff + noteOn**（不是 glide）。拖过八个音会听到八个短音，
  和"插件会重触发包络"是同一件事；真正的滑音要等 MIDI 层的 pitch bend / legato 处理。

# Phase 72 — 采样块的上下边缘改高度 · 高度跟着编组走

用户两条：「采样上边缘和下边缘要可以拖拽来让采样变得更宽或更窄」；「编组里让一个采样变宽
或变窄会应用到其他组副本中，包括右键菜单加高一行和降低一行对采样的影响」。

## 一、上下两条边

长度早就有两块可抓的带子（头、尾），高度却只有右键菜单——"这个块该多厚"要一行一行点。
两条水平边是同一件事转九十度。

### 一次命中，四个答案

```cpp
enum class ClipEdge { none, head, tail, top, bottom };

ClipEdge edgeOfClip (Rectangle<float> bounds, Point<float> p);   // 静态：只算几何
std::pair<int, ClipEdge> clipEdgeAt (Point<float> p) const;      // 只在选中的块里找
std::pair<int, bool> selectedTrimEdgeAt (Point<float> p) const;  // 过滤出头/尾
```

`selectedTrimEdgeAt` 现在**就是** `clipEdgeAt` 过滤的结果，不是另一次判断。理由：
角落里"头"和"上"两条带子重叠，各自判一次会得到两个答案——按下按一个走、光标按另一个画，
于是"光标是上下箭头，拖出来的是长度"。

高度带窄一档：`jmin (band, height * 0.25f)`。一行高的块只有 `keyHeight`（约 18 px），
上下各一条 8 px 的带子会把整块吃掉，中间不剩"拖位置"的地方。

### 几何

```cpp
// 指针所在行就是边
const int lane = jlimit (0, numPitches - 1, pitchAtScreenY (wantedY));

if (fromTop)   // 上边缘：底行不动，向上长
{
    clip->pitch    = origin.pitch;
    clip->laneSpan = jlimit (1, maxLaneSpanFor (origin.pitch), jmax (origin.pitch, lane) - origin.pitch + 1);
}
else           // 下边缘：顶行不动，向下长
{
    const int newBottom = jlimit (0, origin.topPitch(), lane);
    clip->pitch    = newBottom;
    clip->laneSpan = origin.topPitch() - newBottom + 1;
}
```

- **按整行**，因为 `laneSpan` 就是行数：块不跨行，这是模型的性质（P17 起），不是这次的规则。
- **上限 `maxLaneSpanFor(pitch) = min(128, numPitches - pitch)`**：块站在某一行上向上长，
  pitch 120 的块最多 8 行。原来菜单只夹 `laneSpan <= 128`，于是能长到 `topPitch = 247`，
  画在网格外，用户看到的是"加高没反应"。
- 顶边拖过底边 → 一行高（不翻面）；底边拖过顶边 → 一行高。翻转会让块在指针另一侧
  突然长出来，那不是拖拽是魔法。

### 选择集

`applySampleSpanDrag(主块, y, fromTop, 兄弟原件)`，和 `applySampleTrimDrag` 一个模子：

- delta 取**已生效**的（`applied->topPitch() - primary.topPitch()`），不是指针算的——
  行数上限会吃掉一部分。
- delta 加在**手势起点**（`siblings` 是 mouseDown 时的快照）上，不是当前值上。
  组同步已经把主块的绝对高度抄给了别的副本，按当前值加就是两倍高（咬测见下）。

## 二、编组

宽度/窗口/曲线一直是形状（P62），高度现在也是：`applySampleSpan` 每次 move 都调
`syncShapeOfClip()`，和 `applySampleTrim` 一样。右键菜单的加高/降低一行改成走
`growSelectedSamples(lanes)`：作用于整个选择、每块各自一步、副本由同一个 sync 跟上。

### 顺手修掉一个会换掉音频的 bug

`clipShapeLess` 的排序键是 `startBeat` 然后 `pitch`，而 `syncGroupShape` 靠**序号**配对。
以前没有编辑会改 pitch，所以这个前提一直是成立的。拖下边缘正是改 pitch：

```
occ 0: A0(60) B0(48)   排序 B0, A0        →  拖 A0 到 40  →  A0(40), B0(48)
occ 1: A1(60) B1(48)   排序 B1, A1                          B1(48), A1(60)

序号 0 → A0 ↔ B1    名字、path、audio 指针全写过去
```

用户看到的不是"块变高了"，是"两个副本互换成了对方的音频"。排序键改成起点 + 名字，
`pitch` 不再是身份。

`noteShapeLess` 有同样的隐患（拖动音符改 pitch 之后 mouseUp 还会同步一次形状），
这次没动——音符那条路上的断言更多，留到下次。

## 三、自检（606 → 616，10 条）

| 断言 | 判据 |
|---|---|
| 拖上边缘，块向上长高，底部那行不动 | `60+4`，顶 63 |
| 顶边、底边各是一条带子，正中间不是 | `3 / 4 / 0` |
| 拖下边缘，块向下长高，顶上那行不动 | `58+4`，顶 61 |
| 上拖过底、下拖过顶，都停在一行高、不翻面 | `60+1 / 61+1` |
| 长到网格顶行为止，不伸到 128 行外 | 拖到 8 行，再"加高"还是 8 |
| 编组里拖高一块，另一处副本同时变高，位置不动 | `40+6 / 40+6`，副本起点 40 |
| 右键加高一行作用于整个选择 | `50+3 / 44+4` |
| 菜单加高，编组副本也长一行 | `40+7 / 40+7` |
| 拖下边缘越过同组另一块，内容不互换 | 名字仍 `aa / bb`，pitch `40 / 48` |
| 选择里含同组两个副本，变高只落一次 | `70+4 / 70+4` |

咬测 7 处（全部先 FAIL 后还原）：

1. 上边缘拖动带走底行（`pitch = lane - span + 1`）→ 4 条挂。
2. 去掉行数上限（`min(..., 128)`）→ 1 条挂（`120+9`）。
3. `applySampleSpan` 不同步组副本 → 2 条挂（`40+2`、`@ 60 / 48`）。
4. `clipShapeLess` 退回按 pitch 排 → 1 条挂（`@ 48 / 40`，说明配对真的错位）。
5. `growSelectedSamples` 只处理第一个 → 1 条挂（`44+3`）。
6. 高度带占满整块（`height * 0.5`）→ 1 条挂（`3 / 4 / 3`）。
7. delta 加到当前值（`target->laneSpan + delta`）→ 1 条挂（`70+6 / 70+6`）。

第 7 条是重写的。第一版第 9 条断言（选择里含同组两个副本）配的是一段我自己加的
"跳过同组副本"守卫；把守卫改成 `if (false && ...)` 之后断言**照样 PASS**——
因为 delta 取的是起点快照、组同步给的是绝对值，两条路恒等，守卫是死代码。
删守卫、改咬"delta 加到当前值"才真正挂。记进 PITFALLS P72-C。

## 四、边界

- **改高度不改声音**：`pitch` 只决定块画在哪几行（采样播放不看它，`pitchRangeSemitones`
  才是别的功能）。所以"变高/变矮"是纯视觉，不需要 republish。
- **组副本的音高跟着变了**：`sameClipShape` 里 `pitch` 属于形状，拖下边缘会把副本的 pitch
  也设成一样的。这是 P62 定的语义（"members, pitches, lengths, curves belong to the group"），
  所以拖下边缘时副本会跟着换行——不是新行为，是旧规则第一次被踩到。
- **拖拽中每一帧都做一次完整形状同步**（`syncGroupShape` 会排序 + 遍历）。几百个块的工程
  是毫秒以下；没有做"只在 mouseUp 同步一次"的优化，因为中途放弃会导致预览和落盘不一致。

# Phase 73 — 编组：双击进去才能改内容

用户：「编组需要双击进入修改编组内的内容，否则只能拖拽和选中，在编辑状态时，双击空白区域退出编辑。」

## 一、为什么要门

在此之前，点组里的一个音符＝选中并拖动那一个音符。组的边框和名字说明"这些是一个对象"，但它的
成员从第一次按下起就是散的——用户要挪整组，得先点组名 pill 或者组框的空白处；点错一点就只带走
一个成员，而且**看起来一切正常**（拖完组框自动跟着一个成员收窄）。

所以组需要一个"默认是对象，双击才变成容器"的模型。这也是视频剪辑软件里 nested clip 的规则。

## 二、状态与入口

```cpp
int editingGroupId = -1;          // 全会话唯一的组 id，所以不存 layer

bool isGroupLocked (int gid) const noexcept { return gid >= 0 && gid != editingGroupId; }
void enterGroupEdit (int gid);    // 双击成员 / 组框 / 组名
void exitGroupEdit();             // 双击空白 / 点到组外 / 结构变化
```

进入前校验 `layerIndexOfGroup (gid) >= 0`——双击可能比撤销晚一个消息循环到。

## 三、四处拦截（"只能拖拽和选中"要覆盖所有工具）

1. **采样块**（`handlePress` 的 `hitTestSample` 分支最前）：锁 → 整组 `armGroupMove`；
   右键 → 组菜单（`showGroupMenu`）而不是画布菜单。
2. **音符**（`hand` 工具之后、knife/eraser/pencil 之前）：锁 → `armGroupMove`。
   放在这里而不是音符分支里，是因为它必须同时挡住刻刀和橡皮——同一个音符不该"用选择工具碰不得、
   用橡皮一点就没"。
3. **音符的右键**：在 Phase 8 的 chevron 判定之前单独判一次，锁定的组成员右键给组菜单。
4. **光标**：锁定的音符/块显示 `PointingHandCursor`，不再显示 `LeftRightResizeCursor`。
   "光标承诺的操作"和"按下真正发生的事"必须是一句话。

`hand` 工具是例外：平移视图不属于编辑，不受锁影响。

## 四、双击：一个函数，四种位置

```cpp
void PianoRollComponent::handleDoubleClick (Point<float> pos)
{
    if (成员 && 属于别的组)   → enterGroupEdit；选中被双击的那一个
    if (音符)                 → 旧行为（onNoteDoubleClicked）
    if (组框)                 → enterGroupEdit
    if (组名 pill)            → enterGroupEdit
    if (空白 && 正在编辑)      → exitGroupEdit
}
```

顺序就是行为。第 4 条以前是"双击空白什么都不做"，现在它有了一个含义。

**`handlePress` 里还要吞掉第二下**：JUCE 的顺序是 mouseDown → mouseUp → mouseDoubleClick，
所以第二下按下时 `editingGroupId` 还没清。铅笔会先在空白处画一个音符，然后双击处理再退出编辑——
"让我出去"留下一个音符。加一条 `clicks >= 2 && 空白 && 正在编辑 → exit + return`。

## 五、退出：三个来源

1. 双击空白（用户的显式手势）。
2. 按下组外的成员（含别的组）——点出去就是离开，和文本框一样。
3. `layersChanged()` **无条件**清。

第 3 条是本阶段最反直觉的一处。一开始写的是"每次按下检查组还在不在"：

```cpp
if (editingGroupId >= 0 && layerIndexOfGroup (editingGroupId) < 0) editingGroupId = -1;
```

它永远答错问题：组 id 是**序列化**的，撤销把工程恢复时同一个 id 原样回来，存在性检查答"在"，
于是用户从没双击过的组自己打开了。改成 `layersChanged()` 无条件清——加载、撤销、重做、切层
都会经过它。代价是"改个图层名也退出组内编辑"，比"编辑器以为自己还在里面"便宜。

## 六、为了能测，把事件拆开

`mouseDown`（约 600 行）和 `mouseDoubleClick` 拆成：

```cpp
void mouseDown (const MouseEvent& e)          { handlePress (e.getPosition().toFloat(), e.mods, e.getNumberOfClicks()); }
void mouseDoubleClick (const MouseEvent& e)   { handleDoubleClick (e.getPosition().toFloat()); }
```

自检于是能走**真正的按下路径**，而不是只调按下时调用的 helper。这是从 P25 起一直欠着的账：
所有"点击"断言都在测 helper。

代价有两个，都记进 PITFALLS：

- JUCE 8 的 `Point<int>` / `Point<float>` **没有转换构造函数**，`Rectangle<T>::contains` 只吃
  `Point<T>`。函数顶部加 `const auto ipos = pos.roundToInt();` 给工具条/滚动条/标尺/键盘/网格用。
- 三个 `handleXxxAutomationMouseDown` 的签名必须同时从 `const MouseEvent&` 改成
  `(Point<float>, ModifierKeys)`，否则"`e` 未声明"一大串。

## 七、视觉：外圈虚线

第一版是四个 L 形角标 + 加粗。两个问题：加粗已经是 hover/focus 的语义；角标有一个会被组名
pill 吃掉（pill 长在组框左上角，组越短占比越大，越需要提示的组越看不见）。

改成实线框外 3 px 再画一圈 `drawDashedLine`（dash 4 / 3.5，1.4 px），pill 实心 + `surface1` 描边。
虚线绕一圈，四边都看得见。截图确认：`docs/p73.png` 主图不变（没有组在编辑态），
编辑态在临时快照里验证过（金色虚线环套在金色实线框外面）。

## 八、自检（616 → 623，7 条）

| 断言 | 判据 |
|---|---|
| 未进入编辑时点组内音符会选中整组 | `A B` 都在选择里，`editingGroupId < 0` |
| 双击成员进入编辑并选中被双击的那一个 | `editingGroupId == gid`，只有 A 选中 |
| 进入后点谁选谁 | 只有 B 选中，编辑状态不变 |
| 编辑态双击空白退出 | `editingGroupId < 0` |
| 未进入编辑时点组内采样块抓住整组 | 两个音符 + 块都在选择里 |
| 编辑态点组外音符会离开这个组 | `editingGroupId < 0`，只有 outside 选中 |
| 长度只有进去才能单独改 | 关门：2 个起拖 / 不缩放；开门：1 个 / 缩放 |

咬测 5 处（全部先 FAIL 后还原）：

1. 去掉音符锁守卫 → 2 条挂（`A--`、`1 个 / 缩放`）。
2. 去掉采样块锁守卫 → 1 条挂（`---`，块被单独选中）。
3. `enterGroupEdit` 不记状态 → 4 条挂。
4. 双击空白不退出 → 2 条挂。
5. 点组外不退出 → 2 条挂。

第 7 条是重写的。第一版是"组散了编辑状态不挂"，把两处自愈都改成 `if (false && ...)` 之后
**照样 PASS**——因为"点到组外成员就退出"这条规则兜住了：组解散后成员的 `groupId` 变成 -1，

换成"起拖的是什么"才咬得住，因为一次按下里选择集和起拖是**两次独立写入**，只看选择集会漏掉
"选中整组、拖走一个"这种实现（P73-B）。

## 九、边界

- **编辑状态不跨结构变化**：加/删图层、撤销、加载都会退出。这是有意为之。
- **组的删除/复制仍是组级操作**：Delete 在未编辑态删的是整组（因为选中就是整组），
  编辑态删的才是单个成员。
- **`armGroupMove` 没有改**：它在 `isWholeOccurrenceSelected` 时保留选区，所以多选两组再拖

- **没有"进入组"的键盘快捷键**：Enter / Esc 都还没接。Esc 退出的语义要跟曲线框、聚光灯统一，

# Phase 74 — 选中一个成员就是选中它所在的编组

需求一句话：「采样和音符在编组的情况下被选中即是选中其所在的编组」。

## 一、先看现状：三条路只通了一条

P73 之后，"点击"这条路已经通了：`handlePress` 在锁定组的成员上直接 `armGroupMove()`，
它内部会 `selectGroup()`。剩下两条没通：

- **框选**：`simulateMarquee()` 把 `hitsInMarquee()` 的结果原样写进选择，碰到组里一个
  成员就只选那一个。
- **Shift / Ctrl 加选**：`armGroupMove()` 无条件 `selectGroup()`，第二个组一加，第一个组掉队。

## 二、改动

### 1. `expandToWholeOccurrences(noteIds, sampleIds)`（新增，const）

从命中的成员收集 `(groupId, occurrence)`，再把这些出现的全部成员 id 追加进去。
**闸门是 `isGroupLocked(gid)`**：打开编辑的组不扩散，那里成员就是对象（P73 的语义）。

先从命中集**快照**出出现列表，再往两个 vector 里 push——边遍历边追加会走到刚加进去的成员。

### 2. `simulateMarquee()` 调用它

放在 `setMixedSelection()` 之前、空命中判断之后。

### 3. `addOccurrenceToSelection(groupId, occurrence)`（新增）

把整处出现追加到现有 `selection` / `sampleSelection`（去重），一次 `setMixedSelection()` 写入。

### 4. `armGroupMove(..., bool additive = false)`

```cpp
if (! isWholeOccurrenceSelected (groupId, occurrence))
{
    if (additive) addOccurrenceToSelection (groupId, occurrence);
    else          selectGroup (groupId, occurrence);
}
```

三处调用点传 `isAdditive(mods)`：组名 pill、锁定组的采样块、锁定组的音符。
组框那一处不传——外层已经 `if (! mods.isShiftDown())`，Shift 在框内空地是"往里框选"。

`isAdditive(mods)` 是匿名 namespace 的 inline 函数（Shift 或 Ctrl），
与采样命中的 `mods.isShiftDown() || mods.isCommandDown()` 用的是同一对键。

### 5. Shift 框选也变成"加"（顺带补齐）

`marqueeAdditive`（h 里的成员）在 `mouseDown` 的空白分支记录，`mouseUp` 处理完置回 false。
`simulateMarquee()` 里：
- 命中为空：`marqueeAdditive` 时**不清空**（"这里什么都没有"≠"忘掉一切"）；
- 命中非空：旧选择排在前面，新命中追加在后面（列表顺序不重排）。

`setMarqueeAdditiveForTest(bool)` 是给自检的钩子——修饰键读的是按下那一刻，
测试没有真实按下，只能设同一个标志。

## 三、为什么不写进 `setMixedSelection`

写进底层能一次覆盖所有入口，但会静默毁掉 P62：`collectTwinsForEdit()` 用
`isWholeOccurrenceSelected()` 判断"这一处是不是整处选中"，整处就不复制给兄弟。
底层永远给整组 → 用户再也选不出一部分 → 形状同步永远不触发，而且不报错。

底层写入是**记录**，手势是**表达意图**。补全写在记录上，记录就不可信了。

## 四、自检 623 → 628（+5）

1. 框选切到组里一个音符 → 整处回来（音符 + 采样块都选中，组外松散音符不选）。
2. 框选切到采样块的一角 → 同样是整处。
3. 进入组内编辑后框选 → 只选框里的那一个（扩散被 `isGroupLocked` 挡住）。
4. Shift 点另一组的成员 → 前一组的成员留在选择里，新的一组整组加入（含采样块）。
5. Shift 框选 → 加进去；空扫不清空。

## 五、咬测 4 处（全部先 FAIL 后还原）

1. 去掉 `expandToWholeOccurrences` 调用 → 3 条挂（`11000`→`10000`、`00000`、`11100`）。
2. 扩散忽略 `isGroupLocked` → 1 条挂（编辑态 `11000 / 块 1`，应为 `10000 / 块 0`）。
3. `armGroupMove` 忽略 additive → 1 条挂（`00110 / 块 0`）。
4. 删掉加选合并块 → 1 条挂（`00110 / 块 0`）。

## 六、结果

`628 ALL PASSED / 0 FAIL`，`EXIT=0`，零 error 零 warning，`grep BITE Source/` 无残留。
`docs/p74.png` 快照已确认。`formatVersion` 仍 25（纯交互，不涉工程文件）。

## 七、边界

- **粘贴 / 撤销恢复的选择不扩散**：那是新对象或旧快照，不是用户"选中"的动作。
- **Ctrl+A 全选本来就把每处都装进去了**，不需要额外处理。
- **加选只加不减**：Shift 点已在选区里的整处，保持原样（不 toggle 移除）。
  移除会让"Shift 点一下再拖"变成"拖的是空选择"。
- **`noteShapeLess` 仍有 pitch 作配对键的同款隐患**（音符侧，P72 只修了采样侧）。没动。

# Phase 75 — 组内点空白取消选择 / 多选变高要一起动

两条需求：①「在组编辑内部，点击组内部的空白区域要能取消选择」；
②「在组编辑内部，选中多个采样后，调整上下大小有时候多个采样间会不同步」。

## 一、需求 1：组框在编辑态下不是把手

`handlePress` 里组框分支原来是无条件 `armGroupMove()`。P73 让组可以打开之后，这个
分支在**打开状态**下就答错了——框里除了成员就是空白，用户点空白想放掉选择，结果被
重新选中整组并起拖。

改法只有一条判据：

```cpp
if (frameGroup != editingGroupId)
{
    armGroupMove (frameGroup, frameOccurrence, pos);
    return;
}
// 落下去 → marquee 分支 → 清空选择（单击不动指针时不清第二遍）
```

**没有**在组框分支里补"清空选择然后 return"：那样单击能取消选择，但框选没了，而且
是和 `mouseDown` 空分支重复的第二份清空逻辑。让它落下去，两条行为一起拿到。

## 二、需求 2：两个不同的原因

### A. 按下归属错了（主因，跟高度算法无关）

`clipEdgeAt()` 只回答"四条边里的哪条"，四条都不命中时返回 -1，于是 `handlePress`
回退到 `hitTestSample()` —— **倒序遍历，答的是画在最上面的那块**。

两块叠在同一拍同一行（粘贴到自己身上就会叠）时：

- 选中 A 和 C，A 被未选中的 B 压着；
- 按 A 的中间 → 命中测试答 B；
- `edgeId < 0 && ! isSampleSelected(B)` → `setSampleSelection({B})`，A 和 C 掉了；
- 拖起来只有 B 动。

这就是"选中多个之后有时候只有一个跟着变"。修法：`clipEdgeAt()` 在四条边都没命中之后，
再倒序遍历**已选中**的块，点在谁的矩形里就返回 `(那块, none)`。`none` = 抓住了块、
没抓住边 → `handlePress` 保留选区、`armSampleMove()`。

只对已在选区里的块生效，所以"点一个没选中的块 = 只选它"没被改掉。

### B. 写一块同步一块（次因）

`applySampleSpan()` 结尾调 `syncShapeOfClip()`，而 `applySampleSpanDrag()` 对每个块
走一遍，于是循环里同步 N 次。`syncGroupShape()` 是"以这一处为准，其余多退少补"，
N 次调用就是 N 次选源。两处出现**形状本来一致**时恰好等价（所以 P72 的自检全过），
两处**本来不一致**时就轮流当模板，最后停在指针没指过的值：`60+5 / 60+7`。

改法：

- `applySampleSpan(..., bool propagate = true)`，拖拽路径传 false；
- 循环里只写各自的绝对值（快照 + delta）；
- 全部写完后，对涉及的每个 `(groupId, occurrence)` 各 `syncGroupShape()` 一次。

值已经一致，谁当源都一样——"谁当源都一样"才是不依赖遍历顺序的定义。

## 三、新钩子

- `simulateSpanDragFromPress(pressPos, wantedY)`：走**完整手势**（`handlePress` 捕获
  按下快照 → 用 `dragSampleOriginal` / `dragSpanOriginals` 应用一步 → 清状态）。
  `simulateSampleSpanDrag` 拿"此刻"当起点，两者只在"按下到拖动之间没有东西改过块"
  时等价，多选正是它们分家的地方。
- `getClipDragCountForTest()`：按下后武装了几块（采样侧的 `getDragOriginalCountForTest`）。

## 四、自检 628 → 636（+8）

1. 组内点空白 → 取消选择、留在组里（需求 1）。
2. 组内三块一起拖上边缘 → `60+5 / 64+5 / 68+6`。
3. 真实手势（按下上边缘再拖）→ 同样一致。
4. 组内三块一起拖下边缘 → `58+4 / 62+4 / 66+5`（另一套算式）。
5. 按在已选中块的中间，被上层未选中块压着 → 选区不变、起拖 2 块。
6. 同组两处副本同时选中 → 两处高度一样，没选的成员不动。
7. 两处形状本来不一致 → 拖一次停在指针指着的 5，不是 7。
8. 两处成员数不一样 → 拖完两处还是同一个高度。

## 五、咬测 3 处（全部先 FAIL 后还原）

1. 组框无条件 `armGroupMove` → 需求 1 挂（`2 个音符 / 块 1`）。
2. 去掉 `clipEdgeAt` 的"已选中块中间归属" → 叠块挂（`--O / 起拖 1 个`）。
3. 恢复"边写边同步" → 形状不一致挂（`60+5 / 60+7`）。

第 2 次咬测第一版写得太粗（顺手删掉了 `if (bestId >= 0) return`），连带把 P58 的
tail 拾取和 P72 的四边判定一起弄挂 4 条；收紧成"只删第二遍循环"之后精确挂 1 条。

## 六、结果

`636 ALL PASSED / 0 FAIL`，`EXIT=0`，零 error 零 warning，`grep BITE Source/` 无残留。
`docs/p75.png` 已确认。`formatVersion` 仍 25。

## 七、边界

- **"不同步"在物理上仍然存在**：块长到网格顶行（`maxLaneSpanFor`）或被下界 0 夹住时，
  它会先停下来，其余块继续长。这是"不能画到网格外面"的代价，不是 bug。
- **叠块的按下归属只对已选中的块生效**：点一个没被选中的块仍然是"只选它"。
- **`growSelectedSamples`（右键加高/降低一行）没改**：它是"每块各加一行 + 逐块同步"，
  同组两处出现形状不一致时同样会轮流当模板。用户这次说的是拖动，没动它。
