# 2026-10-30

## 文档维护：STATUS.md 压缩（无代码改动）

**动因**：`STATUS.md` 自我定位是「1 分钟读完的索引」，实测 33.9 KB / 215 行，而且肥肉全在四个
单行单元格里——「已完成阶段」一格塞进了 P81 与 P82 的完整叙述，「自检」一格塞进了 P76–P82 的
全部咬测流水，「formatVersion」一格塞进了 v22 起的逐版沿革，「下一步」底下还堆着 P62–P82 的
三十余条经验。新会话按它的指示第一步就读它，等于每开一次会话先把三个历史阶段重读一遍。

**做法**（一个字没丢）：

- 建 `STATUS-archive.md`，把那四段**原样**搬进去（已完成阶段全文 / 自检咬测流水 /
  formatVersion 沿革 / P62–P82 经验）。搬运是程序切的，不是重写的。
- `STATUS.md` 重写成真正的索引：当前状态表（7 行）、下一步（一行）、**最近六轮**（P77–P82，
  每条 2–3 行）、已知边界（原文保留——那是给用户的承诺清单，不压）、阶段 → 细节在哪
  （补齐 P44–P55 / P56–P76 / P77–P82 三段，原来只到 P51 然后跳到 P80，P52–P79 整段缺失）、
  构建、自检、未建成的东西。

**顺带修的两处错**：自检基准还写着 710（实际 714）；源码规模写 87（`find` 实测 88）。

**结果**：`STATUS.md` 33.9 KB → 6.1 KB（-82%），`STATUS-archive.md` 27.8 KB。总量没变，
但「每次会话必读」的那份降到了原来的五分之一。

**留下的判断**：`PITFALLS.md`（80 KB）与 `REFERENCE.md`（62 KB）没有动。它们是**按主题查**
的参考，不是线性读的索引——压缩它们的代价是把"卡住时能翻到那段话"变成"翻不到"。
真正的膨胀源是 STATUS 那一格一格往里堆，不是这两个文件本身。
