# Phase 103 — 增益衰减看得见

## 为什么做这个

上一轮（P102）量的是「断言能不能看见东西」，它补的是延迟补偿。这一轮拿同一把尺子量
**压缩器**：`compGain` / `limitEnv` 从 P46 起就逐样本在变，从来没有一个读者。
于是「它现在压下多少」这个问题，屏幕上没有答案，自检里也没有答案——
诊断五条早就收口了，剩下的都是这种「数字已经在那儿，只是没人接」的活。

## 三个决定

**① 记「这一块乘下去的最小增益」，不是别的三个数。**

- 不是**最后**那个：一个 8 dB 的瞬态在块尾已经放开了一半，读最后那个等于在用户转头
  的一瞬间把数归零。
- 不是**包络**（`compEnv`）：那是探测器上的**电平**，量级相近、含义完全不同。
  报它出来是一个看起来非常合理的错数——实测读成 `96.00`，因为包络从 0 起步，而 0 是「衰减无穷」。
- 不是**乘完补偿的**：补偿是用户自己拧的推子。折进去，一个干 12.2 dB、补偿 9 dB 的
  压缩器读成 3.2 dB；补偿再大一点会被夹成 0，于是「明明在压」读成「什么都没做」。

**② 回落和电平表住在一起。** `decayMeters` 每块按 `24 dB/s × 本块时长` **减**。
放在那里不是图省事：它是「读数不是最大值」这条规则的一部分，和电平表同一个理由
（走带停着也要落）。**但减不是乘**——电平是线性量（乘因子），衰减是 dB（减差值），
两种量不共用一个因子。

**③ 表画在插槽那一行，不画在条子上。** 条级的一根表更显眼、写法也更省事（复用
`levelSource` 的形状），但它答不了「哪一个」：一条链里两个压缩器，表动起来用户得猜。
判据不是好不好看，是**这个数是谁的属性**——`blockMinGain` 本来就住在 `SlotState` 里。
同一条理由反过来用：`DRIVE` 那些行连空轨道都不画，一条空表是一个承诺。

## 被咬的六次

**M1（报包络）** 红 2 条：`reported 96.00 measured 12.21`。
**M2（把补偿折进去）** 红 5 条，第一条正是那个 3.21 vs 12.21。
**M3（不回落）** 红 2 条：一步的 Δ 是 0，且永远到不了 0。
**M4（覆盖而不是取大）** 精确红 1 条 —— 这一条断言是专门为它写的：旁通那一块不能把表打到 0。
**M5（读完不消费）** 红 2 条，其中最刺眼的一条：旁通之后表**涨**了，7.60 → 8.16。
**M6（限幅器不报）** 精确红 1 条。

## 留给下一个人

- **只有 COMP / LIMIT 有表**。托管 VST3 的 GR 要问 `AudioProcessor` 自己，而 JUCE 没有
  统一接口——那是又一条「模型严 / 发布宽」的边。
- **表不区分「压了但没声音」和「没压」**。所以「表停了」不能当成「信号停了」的判据。
- **主输出那条表在 `[numChannels]`**，是全文件唯一一处「条号 == 数组下标」之外还成立的地方。
  加母线 / 编组总线时这张表得跟着变成「按节点」。

# Phase 104 — 削波看得见（一个不会自己回落的读数）

## 方向是怎么选的

上一轮收口后，STATUS 里留的两条候选里第一条是「母线级 send 与侧链」。这一轮开头先把它
**判掉了**：master 不在图里不是遗漏，是拓扑事实（它是终点，成品信号只在下游存在）。
`insertReduction` 与新的 `channelClip` 都用 `[numChannels]` 表示 master，那不是「条号 ==
下标之外的特例」，是「master 是第 numChannels 个节点」；真要加母线，那张表变「按节点」是
**那一次**的事。两个用途各自是死路：当键源必成环，被 send 到就是叠一遍（`out` 在做）。

第二条 `numSends` 可配仍在，但它碰不到任何不变量，随时能不做。

也考虑过**写自动化**（推子能被演奏），读代码时撞到一条硬边界：消费端是
`gain * gate * curve`，曲线是**乘数且只能往下压**（默认 1.0），所以「推上去再推下来」
在当前架构里表达不了。写模式因此不是一个手势，是一次曲线语义的改动 —— 那不该顺手做。

最后选的是混音台缺的最后一块**基本仪表**：没有任何地方告诉你「你爆了」。P103 做了
「压了多少」，但没有「越界了没有」。

## 判断：一个读数会不会自己消失，取决于它记的是状态还是事件

P103 立了「发布取大、按速率落、读完消费」。这一轮写的是它的反面，而且理由是同一个：
那三条成立的前提是**读数记的是一个会自己消失的状态**。削波记的是**事件**，事件不会因为
没人看而变成没发生，所以它不回落、不消费，只在两个时刻清零——用户点它，或者换会话。

`resetMixState`（locate / 停止 / bounce 共用）**明确不碰它**：那是「从零开始量」，
不是「忘掉发生过什么」。

## 实现

- `Source/Audio/OverloadLatch.h`：`overload::isClipped(v)` = `|v| > 1.0`。严格大于
  （0 dBFS 不是越过它），取绝对值（喂进来的是 `getMagnitude`，这一句是给下一个调用者的）。
- `PlaybackEngine`：`channelClip[numChannels]` + `masterClip`；判定搭在 `channelPeaks`
  与 `output.getMagnitude` 上（后者算一次给电平表与闩锁两个读者）。`clearClip` /
  `clearAllClips` / `getChannelClipped` / `getMasterClipped` / `setChannelClippedForTest`。
  `clearAllClips()` 在 `buildSession` 里调，是唯一的自动入口。
- `MixerPanel`：`clipSource` / `onClipCleared`；灯画在**电平表顶端**并**画在最后**
  （满刻度的电平从灯后面过去）；未点亮是暗轨道；命中区 3 → 8 px；`updateMeters` 的
  repaint 条件加 `|| clipSource != nullptr`。
- `-overload` 帧：主输出与 Synth A 亮、其余暗。**不叫 `-clip`**——那个名字从 P29 起就是
  采样块特写。

## 验收

自检 **1053**（1044 + 9），零 error 零 warning。九条里最有分量的是
「四十块静音之后电平归零、灯一格不动」（peak 0.0000 / lamp 1）——它同时证明灯不在
`decayMeters` 那条回路里。

夹具借一个 **ratio 1:1 + 18 dB makeup 的压缩器当放大器**（默认 -6 dB 正弦 + 推子 +6
也够不到 1.0），顺带再证一次 P103 那条「补偿不进 GR 表」：它在放大，表读 0.00。

## 咬测（六条）

| 变异 | 红 |
|---|---|
| `>=` 当削波 | 2（含 -1.0 那条） |
| 不取绝对值 | 1（只有规则那条，引擎喂的全是 magnitude） |
| 灯跟着 `decayMeters` 落 | 1 |
| `resetMeters` 顺手清 | 1 |
| 主输出不判 | **1 → 加固后 2** |
| `clearClip` 空实现 | 2 |

第五行是这一轮最有价值的一课：**「通道爆而主输出不爆」在「主输出永远不报」的实现下
依然全绿**（`!false` 是 true）。加固的办法是把前提也写成断言（先证明同一份材料在
master unity 下会点亮它）。这是 P101-C 同一件事的第三次出现。

## 快照

38 张入库（37 + `-overload`）。同一份二进制跑两遍，抖动集 **17 张**（`-overload` 自己在里面，
因为同一张混音台画面里的电平表是真读数）。与 P103 比 19/37 相同，18 张不同里 16 张在抖动集，
剩下 2 张是 `-clipauto` 一个像素、`-slotparam` 两个像素的抗锯齿取整平局。

这一轮的方法论要点：**唯一一处真改动（每条通道顶端的暗轨道）落在所有混音台帧里，
而那些帧本来就因为在抖** —— md5 判不出「灯画上去了没有」，只能靠一张把两态并排的新帧。

## 留给下一个人

- **只记「这一块里爆过」**：不记次数、不记峰值、不记是哪个采样。要计数器得先决定
  0.3 dB 尖峰连爆十次和一次该不该长得不一样。
- **没有一次清掉所有灯的界面入口**：`clearAllClips()` 只有 `buildSession` 在调。
- **master 只有一盏灯，不分左右**；通道同理。分两盏要双倍高度，而这一条 3 px 是从
  电平表顶端换来的。
- **判的是「样本超过满刻度」不是「D/A 真的夹了」**，中间还隔着系统音量与设备余量。
  这是有意的：修复动作在混音里。
