# Phase 103 — 增益衰减看得见

## 为什么做这个

上一轮（P102）量的是「断言能不能看见东西」，它补的是延迟补偿。这一轮拿同一把尺子量
**压缩器**：`compGain` / `limitEnv` 从 P46 起就逐样本在变，从来没有一个读者。
于是「它现在压下多少」这个问题，屏幕上没有答案，自检里也没有答案——
诊断五条早就收口了，剩下的都是这种「数字已经在那儿，只是没人接」的活。

## 三个决定

**① 记「这一块乘下去的最小增益」，不是别的三个数。**

- 不是**最后**那个：一个 8 dB 的瞬态在块尾已经放开了一半，读最后那个等于在用户转头
  的一瞬间把数归零。
- 不是**包络**（`compEnv`）：那是探测器上的**电平**，量级相近、含义完全不同。
  报它出来是一个看起来非常合理的错数——实测读成 `96.00`，因为包络从 0 起步，而 0 是「衰减无穷」。
- 不是**乘完补偿的**：补偿是用户自己拧的推子。折进去，一个干 12.2 dB、补偿 9 dB 的
  压缩器读成 3.2 dB；补偿再大一点会被夹成 0，于是「明明在压」读成「什么都没做」。

**② 回落和电平表住在一起。** `decayMeters` 每块按 `24 dB/s × 本块时长` **减**。
放在那里不是图省事：它是「读数不是最大值」这条规则的一部分，和电平表同一个理由
（走带停着也要落）。**但减不是乘**——电平是线性量（乘因子），衰减是 dB（减差值），
两种量不共用一个因子。

**③ 表画在插槽那一行，不画在条子上。** 条级的一根表更显眼、写法也更省事（复用
`levelSource` 的形状），但它答不了「哪一个」：一条链里两个压缩器，表动起来用户得猜。
判据不是好不好看，是**这个数是谁的属性**——`blockMinGain` 本来就住在 `SlotState` 里。
同一条理由反过来用：`DRIVE` 那些行连空轨道都不画，一条空表是一个承诺。

## 被咬的六次

**M1（报包络）** 红 2 条：`reported 96.00 measured 12.21`。
**M2（把补偿折进去）** 红 5 条，第一条正是那个 3.21 vs 12.21。
**M3（不回落）** 红 2 条：一步的 Δ 是 0，且永远到不了 0。
**M4（覆盖而不是取大）** 精确红 1 条 —— 这一条断言是专门为它写的：旁通那一块不能把表打到 0。
**M5（读完不消费）** 红 2 条，其中最刺眼的一条：旁通之后表**涨**了，7.60 → 8.16。
**M6（限幅器不报）** 精确红 1 条。

## 数字

自检 **1044 ALL PASSED / 0 FAIL**（`MIN_CHECKS` 1033 → 1044），编译零 error 零 warning。
源码 117 个文件 **91,102 行**（P102 是 90,450）。`formatVersion` 仍 **34**：没有新属性。

与上一轮比 23/36 相同，唯一一张真改动是 `-sidechain` 里 `COMP` 那格底部多出来的
3 px 空轨道（机架区域内只有 `y 114..117` 四行像素变了）。

## 留给下一个人

- **只有 COMP / LIMIT 有表**。托管 VST3 的 GR 要问 `AudioProcessor` 自己，而 JUCE 没有
  统一接口——那是又一条「模型严 / 发布宽」的边。

# Phase 104 — 削波看得见（一个不会自己回落的读数）

## 方向是怎么选的

上一轮收口后，STATUS 里留的两条候选里第一条是「母线级 send 与侧链」。这一轮开头先把它
**判掉了**：master 不在图里不是遗漏，是拓扑事实（它是终点，成品信号只在下游存在）。
`insertReduction` 与新的 `channelClip` 都用 `[numChannels]` 表示 master，那不是「条号 ==
下标之外的特例」，是「master 是第 numChannels 个节点」；真要加母线，那张表变「按节点」是
**那一次**的事。两个用途各自是死路：当键源必成环，被 send 到就是叠一遍（`out` 在做）。

第二条 `numSends` 可配仍在，但它碰不到任何不变量，随时能不做。

也考虑过**写自动化**（推子能被演奏），读代码时撞到一条硬边界：消费端是
`gain * gate * curve`，曲线是**乘数且只能往下压**（默认 1.0），所以「推上去再推下来」
在当前架构里表达不了。写模式因此不是一个手势，是一次曲线语义的改动 —— 那不该顺手做。

最后选的是混音台缺的最后一块**基本仪表**：没有任何地方告诉你「你爆了」。P103 做了
「压了多少」，但没有「越界了没有」。

## 判断：一个读数会不会自己消失，取决于它记的是状态还是事件

P103 立了「发布取大、按速率落、读完消费」。这一轮写的是它的反面，而且理由是同一个：
那三条成立的前提是**读数记的是一个会自己消失的状态**。削波记的是**事件**，事件不会因为
没人看而变成没发生，所以它不回落、不消费，只在两个时刻清零——用户点它，或者换会话。

`resetMixState`（locate / 停止 / bounce 共用）**明确不碰它**：那是「从零开始量」，
不是「忘掉发生过什么」。

## 实现

- `Source/Audio/OverloadLatch.h`：`overload::isClipped(v)` = `|v| > 1.0`。严格大于
  （0 dBFS 不是越过它），取绝对值（喂进来的是 `getMagnitude`，这一句是给下一个调用者的）。
- `PlaybackEngine`：`channelClip[numChannels]` + `masterClip`；判定搭在 `channelPeaks`
  与 `output.getMagnitude` 上（后者算一次给电平表与闩锁两个读者）。`clearClip` /
  `clearAllClips` / `getChannelClipped` / `getMasterClipped` / `setChannelClippedForTest`。
  `clearAllClips()` 在 `buildSession` 里调，是唯一的自动入口。
- `MixerPanel`：`clipSource` / `onClipCleared`；灯画在**电平表顶端**并**画在最后**
  （满刻度的电平从灯后面过去）；未点亮是暗轨道；命中区 3 → 8 px；`updateMeters` 的
  repaint 条件加 `|| clipSource != nullptr`。
- `-overload` 帧：主输出与 Synth A 亮、其余暗。**不叫 `-clip`**——那个名字从 P29 起就是
  采样块特写。

# Phase 105 — 编组框是组的属性（用户报的 bug）

## 报告与根因

用户：「组内的音符有几个在视口外时，对编组区域的显示只判定到视口内部的几个，希望能够保持
编组整体的区域大小不变。」根因一处：`getGroupContentBounds` 在求并集前把**不与网格相交的成员
整块 `continue` 掉**。那两行在兼职两件事——限几何 + 省绘制——只有后者合法。

判据：**几何算「这个东西有多大」，绘制算「这一帧画哪些像素」**。分家之后
`drawGroupBands` / `drawGroupFrames` 各拿一次 `intersects(area)` 做减法，几何一个数都不动。

反证很好用：同一个窗口里 `getGroupAutomationBoxBounds` **早就做对了**——按 `getGroupBeatSpan`
的模型值算宽度、让绘制裁切去裁，注释原文「When the group is scrolled half out of view the box
now goes with it and the paint clip trims it」。两个框，一个好一个坏，差别就是那两行。

## 一处几何，四个读者

`groupFrameOf` → `getGroupContentBounds`，读者：① 组带（band）② 组框（frame）③ pill 落点
④ 替换预览 + 命中测试。所以这一轮一处真改动**牵动了 11 张快照帧**（见下）。

pill 需要两条**互补**规则：
- 左沿夹紧 `jmax(content.getX(), area.getX())`——组的起点滚出视口后名字停在网格左沿；
  理由不是好看，双击改名和右边的自动化 caret 都长在它身上；
- 整组不可见时 `return {}`——否则滚到第 200 小节的组会在屏幕边上留一个悬着的名字。

## 验收

自检 **1059**（1053 + 6），零 error 零 warning。六条：
1. 框伸到滚在视口右边的成员（`frame.right > grid.right`）；
2. **滚到第一个成员出界，宽高与滚动前相同**（1906.5 两边都是它），只是左移；
3. 只剩一半在视口里时，按在框的空白处（拍 40.5、音高 72 那行——正是滚走的那个成员的行）
   命中的仍是这个组（旧代码答 -1）；
4. pill 留在视口内；
5. 整组滚出视口（第 200 拍）框仍然存在且宽不变；
6. 看不见时不悬着一个名字。

咬测三条：
| 变异 | 红 |
|---|---|
| 恢复视口裁剪（旧行为） | **4**（宽 94.5、命中 -1、整组出界框变空） |
| pill 不夹回左沿 | 1 |
| 整组不可见也留 pill | 1 |

主变异**咬不动 pill 那两条**（旧代码里 content 恰好仍在视口内），所以分开咬——记进 PITFALLS。

# Phase 106 — 插件窗口自带试听条（用户报的第二件体验缺口）

## 报告

「打开外部音源界面时，要可以通过与外部音源界面互动预览声音。」

先查了现状，结论有点意外：**按键转发一直在**。P42 就把 `pluginForwarder` 装到了插件窗口和它的
content 上，空格能开始走带、按字母能弹音。所以这不是一个坏掉的 bug，是**三条路同时不通**：
① 那个能力**看不见**，而焦点一落进插件自己的文本框（预制名搜索框）就整排静音
（`handleGlobalKeyPress` 遇到 `TextEditor` 直接放手——那是对的，用户看到的只是「不响了」）；
② 插件**可能根本没有界面**（`createEditorIfNeeded()` 返回空，窗口里只有一句说明）；
③ 其余试听入口（钢琴窗键盘、混音台）全在被插件窗口挡住的**主窗口**里。

## 做法

窗口底部加一条**宿主自己的**琴键带：`AuditionStrip`（两个八度 C3–B4、14 白 10 黑、
可点可按可滑奏），外面套一层 `EditorHost` 把内容区切成「插件占上面、带子占下面」。

四个判断：
1. **它是宿主的，不是插件的**——插件可以没有界面、没有键盘、或者那个键盘只驱动它自己的内部发声，
   而宿主永远能把 note-on 送到槽上。走的是钢琴窗那条 `auditionPreview`，**一条路一个声音**。
2. **窗口要长高，不是把插件压小**——窗口尺寸 = 插件要的高度 + `preferredHeight()`。
3. **按住是一句持续的话**——宿主在最后一次请求之后 420 ms 放开托管预览（P71），所以带子按
   200 ms 的节拍重复说「还按着」；松手就停表，让它自然到期。**松手不是命令，是沉默**。
4. **滑奏要先放后按**——`hold()` 换键前 `releaseHeld()`。

接线：`PluginEditorWindow::setAuditionCallbacks` → `MainComponent::auditionPreview(slotId, …)`；
槽不是构造时捕获的，是按下时用 `slotIdForPlugin(instanceId)` 现查——槽可能在窗口还开着的时候被换掉。

## 两个实现上的坑

**`setContentOwned` 会按内容大小调窗口。** 第一版让 `EditorHost` 以 0×0 出生，结果它被夹到
最小尺寸、再被 `centreWithSize` 二次拉扯，窗口高度停在 182（= `jmax(px(140), h/2)`）。
改成先 `content->setSize(w, h)` 再 `setContentOwned` 就对了。

**`bodyHeight + stripHeight == content.getHeight()` 在任何实现下都成立**，包括「窗口没长高、
带子直接把插件压小 57 px」那种。第一次写的断言正是这一条——它在 M4 下**仍然全绿**。
改成比「插件要的高度」（构造时记进 `requestedBodyHeight`）与「插件实际拿到的高度」之后才有意义：
M4 的 detail 是 `asked 125 got 88 + strip 57 vs content 145`。

## 验收

自检 **1059 → 1067**（8 条），零 error 零 warning。最有分量的两条：
「窗口里有一条试听条，它占的是窗口多出来的高度而不是把插件挤小」（`asked 125 got 125 + strip 57 vs content 182`）、
「窗口里的试听条按下去：音符走的是那个槽那个音高」（`slot 1 pitch 48`）。

第 6 条观察的是 `hostedPreview` 而不是引擎的 `hasLiveNotes()`：headless 没有设备回调，
队列里的 live 事件永远不会被取走，`hasLiveNotes()` 在按下之前就已经是真的——那会变成同义反复。

## 咬测（五条）

| 变异 | 红 |
|---|---|
| 键位表全白（`isBlackKey` 恒 false） | **2 → 补前提后 3** |
| 滑键不先 `releaseHeld()` | 2 |
| 回调装了但没接上 | 2 |
| 窗口不给带子留高度 | 1 |
| `slotIdForPlugin` 恒 -1 | 1 |

# P108 — 音符的默认曲线是一条 80% 的平线

用户一句话：**「音符的自动化曲线默认是80%的直线」**。没有别的要求，也没有解释——所以这一轮
先做的是**拆句子**：代码里有三个「默认曲线」，值各不一样（默认构造 = ADSR；「直线」预设 =
0.7；采样块的空闲曲线 = 1.0 且停用）。问了一次，答案是第一句：**新音符的默认改成一条 80% 平线**。

## 为什么原来的 ADSR 默认是错的

它当年的理由是「合成器音符没有形状听起来不对」。但那个形状**合成器自己已经有了**——于是每个
音符被包络两次：一次是自己那条曲线，一次是合成器的放大器包络。而用户想要「照原样弹」的时候，
反而要先打开编辑器手动拉平。

**曲线是改动，「还没改」是一条线。** 把推荐形状塞进默认值，等于把「取消编辑」从界面里删掉。

## 改了什么

| 位置 | 改动 |
|---|---|
| `Model/NoteEnvelope.h` | 新增 `static constexpr float defaultFlatValue = 0.8f`（唯一那个数） |
| `Model/NoteEnvelope.cpp` | 默认构造 = 平线 0.8；`makeFlat()` 用同一个常量（原 0.7）；`resetToDefault()` 回平线 |
| `Model/LayerModel.h` | `NoteEvent::curves` 的初始值 `makeADSR()` → `makeFlat()`；两处注释跟着改（`idleCurve` 那段说的是「默认构造是启用的」，不是「是 ADSR」） |
| `UI/SampleEnvelopePanel.cpp` | 音量上的「直线」显式要 `makeIdle(1.0f)`：注释两个阶段来写着 "unity for level"，代码给的是 `makeFlat()` 的 0.7 |

| `.github/workflows/selftest.yml` | `MIN_CHECKS` 1059 → **1067** |
| `docs/p108-*.png` | 39 张（这一轮有真视觉变化，所以入库） |

**ADSR / 渐弱 两个预设一行没动。** `MainComponent` 里那处 `makeADSR()` 是快照夹具显式要的

## 三条旧断言被改红，每一处都是「借了默认值」

1. `A note's envelope can be pasted onto a group's lane`——它拿一个**新建音符**的曲线贴到编组
   车道上，然后断言峰值 > 0.95（ADSR 的峰）。默认变成 0.8 平线之后峰值就是 0.8。修法不是把阈值

   `0.7` / `0.35`，注释里还写着「makeFlat 是 0.7」。改成 `NoteEnvelope::defaultFlatValue` 与它的
   一半：**让断言跟着常量走，而不是跟着今天的数字走**。

# P109 — 总览模式：每个图层一条带，音符是一条线段

用户原话：

> 「增加一个总体显示模式，相当于是把每个图层的钢琴窗的琴键宽度压缩到一天线段的宽度，然后有音符的
> 起始位置就显示一条线段，不能编辑，只显示作为提示，然后不同的图层按从上到下的顺序拆开来显示，
> 比如在钢琴窗模式中显示的某个图层的音符，其他图层就只能作为ghost note显示在后面，但是在这个
> 总体显示模式中，其他图层的音符就也压缩起来显示到上一个图层的下面的位置，然后其他的图层依次往下
> 排开这样」

这段话里有四件独立的事，拆开看：**① 第二种布局**（不是放大缩小）／**② 音高维收掉，只留起始位置**
／**③ 只读**／**④ 图层从上到下各占一条带**。第 ④ 条是相对钢琴窗的 ghost 叠放说的，所以它同时
规定了「带号 == 图层号」——不是「有音符的层」，是**全部层的顺序**。

## 设计：换一种画法，不是加一层东西

第一反应是「把琴键列收窄」。**不能这么做。** `ui::gutterWidth` 是钢琴窗和下面自动化窗**共用**的
（`Source/Util/Metrics.h` 的注释里就写着这条教训），收窄它等于让曲线跑到错的拍子底下。

所以「琴键压成一条线」的做法是：**不画琴键**。那一列改成「图层名 + 右侧 3 px 图层色条」，
宽度一个像素没动，时间轴因此与下面的自动化窗逐像素对齐。**换画法不许顺手改坐标系**——
这是 P109 最容易被下一轮违反的一条。

第二条设计判断是**眼睛（P20 的 ghost 开关）在总览里不改成员资格**。它回答的是「要不要叠在我正在
编的那张纸后面」，而总览里没有「身后」。所以眼睛只改亮度：当前层 1.0 / 眼开 0.72 / 眼关 0.40。
带号 == 图层号，不过滤。

## 设计：「略去间隔的琴键」就是「等分」

三种做法，只有第三种两个条件都成立：

| 做法 | 后果 |
|---|---|
| 128 行铺满条带 | 150 px / 128 ≈ 1.17 px 一行。差 1 个半音的两条线重叠，等于什么都没还回来 |
| 按真实半音比例（一个半音 = h/跨度） | 差 12 个半音是差 1 个的**十二倍**——小的那一对又看不见了 |
| **行 = 这一层用到的不同音高，等分** | 差 12 与差 1 **行距一样**；层内相对高低保住了 |

等分就是「略去间隔的琴键」这句话的算术形式。代价是**每层的比例尺不一样**（跨层不可比），
那不是实现没做好，是这句话本身的含义，所以写进了 STATUS 的「留下的几件小事」。

# P111 — `折叠` 从整摞一个变成每层一个

用户原话：

> 「折叠也给每个图层单独加一个，可以单独折叠一个选定的图层」

不是 bug，是**口径**：P110 的折叠回答的是「这一层现在有多挤」，而「多挤」是每层各自的事。
一个 `bool` 管整摞，在「一层六十个音高 + 隔壁两个音高」的工程里逼着用户二选一——折了那边，
这边就什么都看不见。

## 存的是图层 id，不是带号

```cpp
std::set<int> foldedOverviewLayers;      // 图层 id
```

最省事的写法是 `std::set<int> foldedBands`，按下标记。它在**删除上面一层**这件事上立刻错：
「第 2 层折着」变成一个位置，删掉第 1 层之后折叠留在位置 2 上——留给了原来的第 3 层，
而原来被折的那层自己展开。两者都不是用户说的「这一层折着」。

`Layer::getId` 是工程早就用来绑定自动化轨道的那个稳定身份（`LayerModel.h`：
「assigned on construction and never reused」），直接用它。删层留下的死 id 代价是一个整数，
下一次「全部展开」的 `clear()` 顺手清掉——比监听模型删层便宜，也比它少一条会漏的通知。

自检里专门有一条为这个口径写的：折第 2 层 → `stack.removeLayer(0)` → 断言带 0 仍折、带 1 不折。

## 三个入口，一份状态

| 入口 | 管什么 | 亮/状态 |
|---|---|---|
| 左列每层名字右边的小三角 | **这一层** | ▼ 展开 / ▶ 折叠 |
| 齿轮菜单第 8 项 + 子菜单「总览里只折叠一层」 | 全部 / 某一层 | 打勾 = 那一层折着 |
| 工具栏第 12 颗 `折叠` | 全部 | 亮 ⟺ **所有**带都折着 |

按钮的语义选了三种可能里的第三种：**亮 ⟺ 全折，点击 = 把剩下的折完**。
「亮 ⟺ 有任何一条折着」会让只折一层的画面看起来像全折了；「点一下全展开」会让第一次点击
没有任何可见变化。一句话：**按钮的亮是状态，点击是动作，两者不必是同一个集合的补集。**

## 撞到的一个坑：`addNote({0, 84, 4.0, 1.0, 0.8f})` 里的 4.0 不是 bpm

`NoteEvent` 的字段顺序是 `{ id, pitch, startBeat, lengthBeats, velocity }`，P110 的夹具
写的是 `{ 0, 84, 4.0, 1.0, 0.8f }`，意思是「第 4 拍起、长 1 拍」。我照抄过来，却按
「起点 0、长 4 拍」写断言，于是「点箭头只换画法」那条红了：

```
[FAIL] 点箭头只换画法：选区还在、音符数没变、音符的起点没变
       (1 个选中 / 选对了 yes / 音符 6 -> 6 / 起点 4.000)
```

detail 里那个 `起点 4.000` 一行就定位了。夹具改成 `{ 0, 84, 0.0, 4.0, 0.8f }`，断言不动。

教训不是「记住字段顺序」，是**失败的 detail 要能一句话指到错的地方**——这条断言本来只写
「选对了 yes」，那样就只剩猜。
