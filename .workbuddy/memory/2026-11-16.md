# P113 — 折起来的那条带自己也变薄

用户一句话：「折叠之后，整个图层在总览中的宽度也变成一条线的宽度」。

P109–P112 把每条带钉死成 **1/N**：折叠只回答「几行」，从不回答「占多少地方」。于是折起来的层
仍然占着整个 1/N，只在正中间画一条线——上面一半空气、下面一半空气。用户这句话要的是另一半。

## 改法：带宽从「一个只读自己的数」变成「整摞的派生量」

`getOverviewBandBounds` 先数 `folded` / `open`，再：

```
slice = 网格高 / count
thin  = min (16 设计像素, slice)                       // 折起来的带
share = open > 0 ? (网格高 - thin * folded) / open : slice
heightOf(i) = (open > 0 && 折着) ? thin : share
```

两条边仍然各自取整（两种高度混在一张图上时这条更要紧），所以整摞仍然首尾相接铺满网格。

**16 不是新数**：它就是 `drawOverviewColumn` 里那句「一个名字需要 16 px 的条带」，也是折叠
**可逆**的最小高度——小三角是 `min (13, 高度 - 4)`，16 留得下 12 px 的按钮（实测 12）。薄的
代价原本可以是「折完之后左列只剩色带、展开只能走菜单」，这一轮没有接受那个代价。

两条边界各一个答案：

- `open == count` → 逐点等于 P109 的等分（未折过的画面一像素不动）。
- `open == 0` → **也回等分**：没有人接收那块高度，均摊是唯一不把窗口画成大片空白的答案，
  而且那正是 P110 说的「像现在一样」。另一条路（全折也压成 n 条细线堆在顶上）不难写，画面上
  像坏了。

## 改口的三条旧断言（不是修 bug）

1. P111「折叠一层不移动别人的像素」——**这一轮反转了**，现在是「别人的带反而变高，线段跟着新的
   等分往下走」。反转要在注释里写明是哪一轮翻了哪一条。
2. P111 (5)(6) 按下去用的是前一条算出的 `t1` / `t2`。折一层之后那些坐标落在空白处，**按下去什么
   都不会发生**，而「只有它自己翻了过来」照样变绿（它本来就没翻）。改成每次按之前重新问几何，
   并钉住「它真的翻了面」。
3. P111「箭头折叠前后在同一个位置」——它跟的是**带**，带挪了它就挪。真正不变的是「箭头永远落在
   自己那条带的正中间，而且塞得进去」。

# P114 — 折叠带的厚度 = 一条线的厚度

用户一句话：「我说的是总览界面中，图层的高度，在折叠的情况下，跟一条音符占位符的宽度相等，
或者略宽一点」。

P113 我以为「折叠之后整个图层变成一条线」是「带变薄」，压到 16 设计像素就交了。用户看完说
不是这个意思——**他要的是那条带本身就是一条线的厚度**。P113 的 16 是从「名字要 16 行高」和
「13 px 三角要装得下」推出来的，两个理由都对，都不是「这条带该多厚」。实测带 21 px、线 6.5 px，
三分之二是空气。

## 改法

```
thin = min (7 设计像素, 等分)          // 7 = 线厚上限 5 + 上下各一像素缝
折叠态线厚 = jlimit (1.5, pf (5), 带高 - pf (2))
```

第二条是关键：只改第一条会得到一条 2.7 px 的游丝，因为线厚公式里 `band * 0.30` 在单行时
**就是「带高三成」**。带是因、线是果，只改因，果自己就坏掉。判据用 `rows == nullptr`
（调用方只在折叠时传空表），**不是** `count == 1`——展开的单音高层也是 1 行，那样 133 px 的带
会长出一根填满它的柱子。

缝为什么必须留：两条相邻的折叠带各占满 5 px 会糊成一根 10 px 的粗条，「哪一层折着」就没人
答得出来了。

## 开关：不许消失，但可以换形状

带里放不下名字，也放不下 13 px 的三角。P113 的注释早就写着这个代价（「再薄只能走菜单」），
用户要更薄，所以这一轮必须正面回答。

答案：`getOverviewFoldToggleBounds` 在「三角装不下 + 这条带折着」时返回**整个列宽 × 带高**
（实测 96 × 9）。P111 的规则是「开关长在折叠发生的地方」，不是「开关必须是个三角」。三角照画，
按**短边**量尺（`min (宽, 高) * 0.30`），9 px 带里约 5 px 高——图中放大 6 倍能看见。

**第一版写错了**：判据只写了「折着」。于是 `-overviewfold`（全折）也变——全折回等分，每条带
133 px 高，本来就装得下三角，却被降级成整条带，三角按带高量成跟带一样大。帧比对当场抓到
（那三张帧与 p113 不再相同），加上「三角真的装不下」这个条件之后逐字节回到相同。
