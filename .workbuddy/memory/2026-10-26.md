# Phase 22（六条）

## 需求
1 多选拖动时最左音符到 0 就整块停住；2 选中/未选中区别更大；3 钢琴键能按响（走该图层挂的音源）；
4 编组内联框左右与组左右对齐，曲线左右与框左右对齐，不留空；5 菜单栏（文件：新建/打开/保存/另存为/退出；
编辑：撤销/重做/复制/剪切/粘贴）全部绑快捷键；6 可以选中内联框复制/粘贴自动化曲线，粘贴时问是否拉伸
（不拉伸 = 短则截断，长则后面补 0）。

## 做法
- **刚体拖动**：把夹紧抽成 `PianoRollComponent::clampMove(originals, rawBeats, rawPitch, snap)`，
  夹的是 **delta**：`jmax(delta, -minStart)`，右端 `latestStart - minStart`；垂直同理
  `jlimit(-minPitch, 127 - maxPitch, pitchDelta)`。吸附也只作用在块上（锚 = 最左音符），
  逐音符吸附会把刻意的离网格音符悄悄搬走、顺手改掉间距。单音符行为与原实现逐位相同。
  公开给自检，避免伪造 MouseEvent。
- **选中更醒目**：主体 `tinted.brighter(0.30)` + 白色 2 px 环 + 四角括号（`bounds.expanded(1.5)`，
  宽 <12 / 高 <6 不画括号）。悬停环仍是 1.2 px，不抢。
- **琴键能按**：`mouseDown` 里键盘区分支排在标尺/网格之前（原来落到 "不在网格 → return"）。
  `auditionPitchOnActiveLayer` 用 `routing::layerSlotId`（裸键没有 note、没有 group，层默认就是答案），
  拖过键区逐键 retrigger，`pressedKeyPitch` 只管画和去重。
- **框对齐**：`getGroupAutomationBoxBounds` 去掉 22 px 下限和 `jlimit` 夹进网格，
  `x = screenXForBeat(start)`、`width = end - start`；`getGroupCurveArea` 改名
  **`getGroupCurveBounds()`** 并去掉水平内边距（只砍底部 30 px 参数格 + 上下 6 px）。
  框跑到网格外靠 paint 的 `reduceClipRegion(grid)` 裁。窄组会退化成几像素宽的框——诚实换对齐。
- **菜单栏自绘**：`menuBarBounds = area.removeFromTop(ui::px(24))`，两个 item 固定 54 design px，
  `fill{File,Edit}Menu` 用 `PopupMenu::Item.shortcutKeyDescription` 显示快捷键（LookAndFeel_V4 会画）。
  `kCommandKey` 按平台给 "Ctrl+"/"Cmd+"，和 `keyPressed` 里那几条挨着写。
  保存 = 有 `currentProject` 直接写（不弹"已保存"），没路径才转 `askToSaveProject`；退出 =
  `handleCloseRequest()` + `systemRequestedQuit()`（和关闭按钮同一条路）。
- **曲线剪贴板**：`CurveClip { points(距源起点的拍偏移), lengthBeats, target, fromGroup }`。
  音符包络 = `time × lengthBeats`，组 lane = `beat - span.start`，两个方向各一处转换，
  所以音符曲线能贴到编组上（自检里验了 ADSR 贴组，峰值落在 10.24）。
  粘贴：stretch 缩放；不拉伸时 `beat > 目标长` 丢弃，**只有目标更长才补 0 尾巴**
  （三连点：原值到末尾前、末尾 0），目标更短就截断后由最后一点保持——目标短却在末尾砸 0
  等于凭空造出一个原曲线没有的断点。
  `curveSelection` = 打开且被点过的那个框；画布别处一点就清（框不关，方便对比两条曲线）。
  Ctrl+C/X/V 与编辑菜单同一个入口 `canCopyEditSelection()`：**选中的曲线优先，否则音符**。
  剪切曲线 = 复制 + 放平到中性值（level 1.0 / pan 0.5，**不是 0**）。
- 工具条新增 `statusText` 快闪（`flashStatus` + `juce::Timer` 2200 ms），因为复制是哑动作。

## 踩坑
- 组框右端与最后一个音符的右端差 1.5 px：`getNoteBounds` 把音符宽度减了 1.5（邻居间隙），
  自检断言要写 `box.right >= note.right && 差 < 2`，别写绝对相等。
- `juce::String + float` 没有匹配的 `operator+`，详情字符串一律 `juce::String (value, 1)`。
- 空格里的 `if (hasPaintState) ... else if (statusText) ...` 顺序要状态优先：先判断 status。

## 结果
221 项自检 ALL PASSED（+10），零错误零警告。产物 docs/phase22{,-blank,-mixer,-groupauto,-settings-*}.png。

# Phase 23 — 选区挂载 / 混音台布局 / 通道互送

## 需求
1. 组和音符选中后，直接点音源机架的音源即可切换它们挂载的音源。
2. 通道条宽度不变；删除通道条不删主输出；主输出放到最左；超出可显示范围时底部出水平滚动条。
3. 普通通道默认输出到主输出、主输出默认输出到 audio out；每个普通通道加下拉菜单选输出通道
   （通道 1+2 → 通道 3 → 主输出）；主输出不加下拉。

## 实现要点
- **选区挂载**：`PianoRollComponent::mountSelectionTo(slotId)` 是唯一入口。整组选中 → 写 `group.outputSlotId`
  并清掉组内每个音符的 `outputSlotOverride`（override 优先级更高，留着会让组的 chip 说谎）；散音符 → 每音符
  override（复用 `routeSelectionTo`）。机架卡片 `RackPanel` 新增 `selectionActive`（**不是** `focusActive`：
  "有选区"和"聚光灯在哪"是两个问题），由 `MainComponent::applyFocus()` 统一维护；有选区时普通点击 = 挂载，
  无选区仍只看，Alt+点击永远挂载。卡片菜单 33 也改调同一个函数。
- **混音台布局**：`displaySlotFor/channelForDisplaySlot`（master → 槽位 0）；`stripWidth = ui::px(92)` 固定宽度
  （9 条 1080 px，默认 1097 px 视口刚好不滚）；`getStripsViewport()` = stripsArea 去掉滚动条高度，绘制
  `reduceClipRegion`、命中先过 viewport；手绘水平滚动条（thumb/track/滚轮全改 `stripScrollX`）。
  `deleteLastStrip` 只减通道数量，master 选中态保留；`updateMeters` / `paint` 一律按槽位循环（旧代码在
  通道数 < 8 时会多画一条不存在的通道）。
- **通道路由**：`MixerModel` 新增 `channelOutputs`（默认全 master）+ `getChannelOutput/setChannelOutput/wouldLoop`
  + `sanitiseOutputs()`（缩通道/复位时把悬空目标回落 master；环路在模型层拒绝）。
  `ChannelMix::output` 随发布冻结；`PublishedSchedule::channelOrder` 在 `publishSchedule` 里拓扑排序（源在前，
  成环则强制按 index 兜底），`renderInto` 的 Stage 2 按表走：dest 是通道就 `addFrom` 进那条总线并置 `busUsed`，
  否则进 output。`channels` 现在**无条件发布 8 条**（没有 mixer 时等价于旧行为）。工程格式 v10 `<Channel out="N">`，
  提交顺序先 count 后 output。

## 踩坑
- 通道条原来用 `area.getWidth()/stripCount` 均分，master 在末尾；改成固定宽度 + master 在 0 位后，
  所有 `for (ch = 0; ch < getStripCount())` 的循环都必须换成槽位映射，否则会画到不存在的通道。
- 自检详情串里读 `getMaxStripScroll()` 要在窄窗口**期间**存下来，恢复宽度后再读就是 0（断言看着像失败）。

## 结果
233 项自检 ALL PASSED（+12），零错误零警告。`--save`/`--export` 往返 MD5 一致。
产物 docs/phase23{,-blank,-mixer,-mixer-narrow,-groupauto,-settings-*}.png + phase23.log。

# Phase 24 — 局部挂载 / 插件参数自动化 / 组整体复制 / 组框网格吸附

## 需求
1. 组整体挂到某个音源后，单独选组内一个音符再点音源，只改这个音符，组内其他不变。
2. 挂到外部音源后，音符内联框与组内联框的参数菜单要能选该插件的真实参数并驱动它。
3. 复制粘贴组 = 复制一个整体对象，粘贴出**第二个组**（含挂载、电平、曲线），不是把音符塞回原组。
4. 组下拉自动化框的网格与钢琴窗网格对齐；吸附开启时曲线打点/拖动吸附到网格。

## 实现要点
- **局部挂载**只改一处：`PianoRollComponent::mountSelectionTo()` 先问 `isWholeGroupSelected(groupId)`
  （成员数 == 选择数 && 每个选择都属于该组）。不是整组就 `routeSelectionTo()` 走逐音符 override，
  而 override 在 `routing::resolve()` 里本来就压过组挂载 —— 优先级不需要新写一遍。
- **插件参数**走 `Model/PluginParam.h`：`PluginParamInfo{index,name,defaultValue}` + `PluginParamLister`
  （std::function，只许消息线程调）。UI 永远拿不到 `PluginHost*`，MainComponent 装 lister，
  空名字回落 `参数 N`。
- `NoteEvent::modPluginParam` / `NoteGroup::pluginParam`（-1 = 未指定）。内置三个目标与插件参数可无损互切：
  切内置只清 `modPluginParam`，切插件只置索引。
- 组 lane 从 2 条变 3 条（`GroupAutomationTarget::plugin`，`numGroupAutomationTargets = 3`）；
  工程格式 v11：`pluginparam=` + `<Automation target="plugin">`。
- 发布期统一成绝对拍：音符 `note.startBeat + p.time * lengthBeats`、组直接是绝对拍。
  `PublishedSchedule::pluginParams` 里 `priority` 组 1 < 音符 2，`stable_sort` 后按序应用 —— 
  音频线程没有任何"谁赢"的分支。`applyHostedParamAutomation()` 只在 `|现值-目标| < 1e-4` 时写，
  否则插件编辑器每块都重绘。
- **组复制**：`GroupClip` 刻意**不保存 `NoteGroup`**（id 私有、由 `addGroup` 分配），只存名字、挂载、
  电平、三条 lane 的开关与点、以及每个音符的相对偏移。粘贴先 `addGroup(uniqueGroupName(...))`
  再逐条落音符，组 lane 点 `beat + delta` 平移。
- **网格对齐**：`drawGridInside()` 与钢琴窗 `drawGridLines()` 共用 `screenXForBeat` + `gridDivision`
  + 同一套 bar/beat/16th 强调与 `floor(x)+0.5f` 像素对齐；打点与拖动都过 `snapCurveBeat(b, span)`。
  自检断言"曲线区 x/宽度 == beat 0 的 x / N 拍的宽度"——任何装饰性网格都过不了这条。
- `openGroupAutomation()`：目标是 plugin 但 `!drivesPluginParam()` 时回落 level 车道
  （发布端会跳过 `pluginParam < 0` 的 lane，打开一个背后没东西的框等于教错人）。

## 踩坑
- **`--snapshot` 静默退出、exit=127、无产物**：事件日志把故障模块记成 `nvwgf2umx.dll`（NVIDIA 驱动），
  极具误导。PowerShell 取退出码 -1073741571 = `0xC00000FD` = **栈溢出**。`runSelfTest()` 是单个巨帧，
  裸 `{}` 不释放局部变量，Phase 24 四组新局部变量直接撑爆 MSVC 默认 1 MB 栈。
  修法：新块一律 `[&]{ … }();`，CMake 加 `/STACK:8388608`。
- 断言 `paramCount == 1` 失败：JUCE 把 MIDI 控制参数也塞进 `getParameters()`（实测 2082 个）。
  改成按名字断言 `paramName == "Level"`。
- 断崖式曲线别落在 `renderWindow` 的高亮/比较分界上，否则半段 RMS 的比较点正好在断点。
  drop 从 0.25 挪到 0.35。
- 自检"A note on the internal synth publishes no plugin curve"最初写反了：组还挂在外部音源上，
  它那条 curve 本来就该留着。要组和层都指向内部音源才断言 `pluginParams.empty()`。
- `isGroupClipboard()`/`getGroupClipboardName()`/`getGroupClipboardLiveLanes()` 的注释写着
  "the edit menu's status line uses it"，但编辑菜单一直在说"N 个音符"——补上，否则菜单描述的是
  一次永远不会发生的粘贴。

## 结果
243 项自检 ALL PASSED（+10），零错误零警告。产物 docs/phase24{,-blank,-mixer,-mixer-narrow,
-groupauto,-settings-*}.png + phase24.log。

# Phase 25 — 编组可拖 / 顶栏图标 / 分栏跟手 / 127 通道 / 单声道监听 / 单音符拉伸

## 需求（九条）
1. 编组无法被移动。 2. 撤销重做改图标。 3. 保存/载入/导出放到新建与撤销之间。
4./5. 文件树与编组栏的分界线竖直位置必须和鼠标一致（鼠标移动范围不许大过分界线）。
6. 混音台通道上限提到 127。 7. 通道条加单声道监听按钮。
8. 组内左右两个音符，拖右边尾部会把左边尾部一起改掉。 9. 音符尾部自动化按钮右移一点，
   但要留下拉伸带。

## 实现要点
- **编组能被拖起来**：组之前只有「点标签 → 选中」这一条路，选中之后没有任何拖动入口；
  组框（drawGroupBands 那个圆角边）落在空地上时还会掉进 marquee 把选择清掉 —— 一个画成像
  对象的东西不能拖，就是"编组无法移动"。现在两条路都指向 `armGroupMove(groupId, pos)`：
  点标签（getGroupLabelAt）与点框内空地（新增 `getGroupFrameAt`，**只认激活图层**，
  且排在音符命中之后）。Shift 不抢，组内加选 marquee 仍然可用。
- **拉伸只作用于被抓住的音符**（第 8 条）：`dragResizeNoteId` + `resizeTargetId()`，
  两个 resize 模式只改这一条。原来循环 `dragOriginals` 把整组尾巴拉成一条线的元凶。
  数学只有一份：`applyNoteResize(origin, wantedBeat, fromTail)`，拖动和自检都调它。
- **分栏跟手**（第 4/5 条）：`VerticalSplitter` 从「增量 delta」改成「绝对位移」——
  `onDragBegin` 记录起始高度、`onDragTravel(totalTravel)` 用 `e.getScreenY()` 减锚点。
  旧实现 `lastY += dy` 会把被 clamp 掉的越界量**永久丢失**：拖过底线再拖回来，
  分界线还停在底线，鼠标已经跑出两百像素。测试钩子 `simulateDrag(travel, continue)`。
- **顶栏**：撤销/重做改自绘图标（32 px 板 + 弧形箭头，箭头在它回到的那一侧）；
  保存/载入/导出搬进新建与撤销之间（`getFileClusterBounds` 现在是这三者的并集，
  右端只剩工程名）。设备状态文字的上界改用 `getProjectNameBounds()`。
- **127 通道**：`numChannels = 127`（容量 + master 哨兵）、新增 `defaultChannels = 8`
  （新会话仍然开 8 条）。发布端 `fresh->channels` 与拓扑排序**只跑 live 通道**，
  否则每次编辑都要付 127² 的排序代价。插入链按需准备：`chainsReady` 只增不减，
  消息线程 `prepareChannelChains(n)` 先准备好再发布 —— 128 条链的延迟线约 90 MB，
  一次全开是浪费。
- **单声道监听**：`MixerModel::channelMono`（工程格式 v12 `mono="1"`），
  `ChannelMix::mono` 冻结发布，引擎在**插入之后、求和之前**做 (L+R)/2 —— 先求和会让
  混响/延迟吃到单声道源，那是另一个声音而不是另一种听法。按钮放在 dB 读数行右端
  （92 px 条唯一还有空隙的地方），`monoButtonHasOwnPixels()` 由面板自己回答。
- **工程文件**：`out` 的 master 哨兵从 8 变成 127。读 v11 及更早的文件时 `out="8"` 必须
  翻成 master（`legacyMasterEight`），否则老工程会把主输出读成通道 9。写入只写 live 通道
  （外加仍带插入/路由的隐藏通道），不再固定 127 个 `<Channel>`。
- **音符尾部按钮**（第 9 条）：右侧间隙从 `gap(3)` 改成 `kNoteHandleTailAir(1)`，
  拉伸带宽度不变；`minimumWidth` 跟着改。

## 踩坑
- **`--snapshot` 又一次栈溢出（0xC00000FD）**，这次是在 `runSelfTest` **入口**就炸 ——
  连第一行 trace 都打不出来。原因：优化器会把立即调用的 `[&]{}()` 内联，局部变量落回
  同一个帧；这轮加了 MixerModel（128×8 组插入设置）与 PlaybackEngine（128 条插入链），
  8 MB 顶不住。改成 `/STACK:67108864`。**判断方法**：`cmd /v:on /c "exe ... & echo !ERRORLEVEL!"`
  才能拿到真退出码（`%ERRORLEVEL%` 是解析期展开，永远是 0；bash 只给 127）。
- 混音器几何 getter 都是 private，自检从外面调不了 —— 改成让面板自己回答
  （`monoButtonHasOwnPixels()`），比把一堆矩形开封更稳。
- 自检里新音符的 pitch 别乱选：默认滚动位置在**音域中段**（60 附近的音符 y≈524，
  已经在 520 高的画布外），`getGroupContentBounds` 会算成空。用 78/80 这种中音。
- 机架卡片的「发送到混音器通道」子菜单 id 原本是 `21 + ch`，通道上限一旦大于 8 就会
  撞上同一菜单里的 30/31/32/33/34/40。改成 `kSendToChannelBase = 1000`。
- 自检里"控制器停在 8 条"那条断言把 `countBefore == maxChannels` 写死了；现在
  `defaultChannels != maxChannels`，要同时断言两个数并把会话恢复回 8 条，
  否则快照会拍出 127 条空通道。

## 结果
254 项自检 ALL PASSED（+11），零错误零警告。产物 docs/phase25{,-blank,-mixer,-mixer-narrow,
-groupauto,-settings-*}.png + phase25.log。


# Phase 26

## 需求（四条，第 3 条由用户中途更正）
1. 混音台主通道也要有单声道按钮。
2. 包括主通道在内，每条通道条都要一根**竖直双声道**电平表。
3. 减号（删除通道条）最多只能删到**还剩八个普通通道**——到 8 条就删不动了（原话更正过：
   先前理解成"剩下八个普通通道之内"会被读成还能删到 1，实际是地板 = 8）。
4. 所有通道条都可删除；被删的通道条如果之前有音源发送到此，那些音源改为"不发送"。

## 实现要点
- 地板：`MixerModel::deletionFloor = defaultChannels = 8`，`canRemoveChannel()` 是唯一判据；
  面板的 `－`（表头与每条通道名称行右端）在这一条上标灰而不隐藏，因为"删不动"要说明原因。
- `removeChannelAt(i)`：关缝 + 重编号。`inserts`/`channelMono`/`channelOutputs` **三张表都要下移**，
  然后值里 `== hole → master`、`> hole` 各 `--`。头版只下了前两张，结果通道 6 丢目的地、
  通道 7 留着别人那一条——自检的 `out4/out6` 才把它抓出来。
- 机架发送的重编号放在 `MixerPanel::deleteStrip`（模型不认识机架）：先拔 `== i → -1`，再 `> i → --`。
- 立体声表：`channelMetersL/R` + `getChannelPeakSide`，主输出复用 `masterMeters[0/1]`（`getMasterPeak(side)`）。
  每格两根 4 px 柱，`getMeterBarBounds` 派生；自检问 `stereoMeterHasOwnPixels()`。
- 主 MONO：`MixerModel::masterMono` → `PublishedSchedule::masterMono`，在**主推子斜坡之后**折叠
  （通道是"信号离开条子"处折叠，主输出是"离开声卡"处折叠，同一个含义）。
- 格式升到 v13（`<Mixer masterMono>`，缺失=关）。

# Phase 33：清扫变成不变量 / 投放即选中 / 走带开关 / 树默认折叠

## 需求
1. 钢琴窗没有采样了 → 采样音源删掉：P32 声称做了，实际没生效。
2. 采样刚拖上钢琴窗时默认选中高亮，并高亮它对应的采样音源。
3. 文件树加载完成时不要展开所有文件夹，默认全部折叠。
4. 停止状态下按播放/空格 = 播放；只有在播放中按空格/停止才是停止（播放头归零）。

## 根因（第 1 条）
规则写成了"回调"：`deleteSelectedSamples()` 里调 `onSampleReferencesChanged`。可块消失的路
不止一条（Delete、右键删除、Ctrl+X、撤销、代码直接改模型），只有第一条会调。P33 把它挂到
`layersChanged()` / `notesChanged()`（模型通知），并加 `restoringHistory` /
`suspendSamplerPrune` / `pruningSamplers` 三个护栏 + 空机架快速通道。

## 做法
- **清扫**：`pruneOrphanSamplerSlots()` 由两个模型通知调用；`buildSession` 与
  `project::load` 期间挂起；**粘贴时**若槽已不在，`rack.addSampler(clip.audio, path, name)`
  重新登记（剪切=移动而不是剪成悬空）。
- **投放即选中**：`addSampleAt()` 末尾 `setSampleSelection({newId})` → 通知 → 宿主
  `updateRackRoutingFocus()` → `focusedSlotId` = 该块的 sampler 槽。`-sampler` 快照不再手动

## Phase 41 — 选中外部音源后，电脑键盘一直响

用户：「选中外部音源后，电脑键盘输入的 midi 会一直持续，导致音源一直响」。

另外 all-off 处理完展开的 note-off 之后**清空整张表**——没人按着，就不该还指着音源。

**为什么"6 秒后自己停"是更坏的表现**：插件槽的 `tailFrames` 只有 6 s，尾音过后不再
processBlock，但 `numHeld` 还挂着 → 回收条件是 `numHeld == 0 && tailFrames <= 0`，槽永远不还 →

### 一、插件窗口前台时，空格和音符都不响应

**根因是窗口归属，不是键表。** `PluginEditorWindow` 是**独立顶层组件**（P9 起为了能单独
最小化/关闭）。JUCE 的按键从 `ComponentPeer` 下来，只沿**自己那条父链**往上走：
插件窗口 → 自己的 content → 到底。`MainComponent` 根本不在那条链上，所以主窗口的
`keyPressed` 一辈子收不到插件窗口的按键——不是"被插件吃掉了"，是**从来没送到过**。

**改法**：窗口自己装转发器。

```cpp
// MainComponent.h
class PluginKeyForwarder final : public juce::KeyListener
{
    bool keyPressed (const juce::KeyPress& key, juce::Component*) override
    { return owner.handleGlobalKeyPress (key); }
    bool keyStateChanged (bool, juce::Component*) override
    { return owner.releaseTypingKeysThatAreUp(); }
};
```

`handleGlobalKeyPress` 只做一件事：有 `juce::TextEditor` 拿着焦点就 `return false`（放行），
否则转手调 `keyPressed(key)`——**键表只有一份**，插件前台和主窗口前台的映射不可能走岔。
`keyStateChanged` 一并转发，是因为 JUCE 没有 key-up 事件，松手全靠这条（P39 的结论）；
只转 keyPressed 会得到一个"按住不放"的插件。

装两层：

```cpp
void PluginEditorWindow::setKeyForwarder (juce::KeyListener* listener)
{
    keyForwarder = listener;
    addKeyListener (listener);
    if (auto* content = getContentComponent())
        content->addKeyListener (listener);
}
```

两层都要，是因为焦点可能在插件自己的某个子组件上，而中间只要有一层不往回传，
`KeyListener` 就接不到。代价是同一件事挂两次 —— 但 `keyPressed` 返回 true 就停，
不会重复触发。

### 二、「创建自动化 ▸」母菜单

改之前，`创建自动化 · 滤波器` / `创建自动化 · 音量` 这类平铺项在**五个地方**各写一遍：
机架卡片、通道条、编组、钢琴窗空白处、自动化窗口。加第三种目标（就是需求 3）要改五处。

收成母菜单，并且把"同一件事"抽成一对函数：

```cpp
void addSlotAutomationItems (juce::PopupMenu&, int slotId, int idBase);
bool applySlotAutomationChoice (int result, int slotId, int idBase);
```

- 叶子项：`idBase`（滤波器）/ `idBase + 1`（音量）/ `idBase + 2`（音源参数 ▸ 子菜单）
- 参数项：`idBase + kSlotAutoParamBase + index`，`kSlotAutoParamBase = 10000`
- 卡片菜单保留 `idBase = 30`（32 仍是展开/收起），通道条 `idBase = 1`
- master 通道没有音源 → 一条禁用项，不隐藏

**id 基址为什么是 10000**：`PopupMenu` 的 id 空间是扁平的，子菜单不占 id，所有叶子项
共用一个 `result`。卡片菜单当时已经用掉 `10..13 / 20 / 30..41 / 200+n / 1000+channel`，
顺手拿 100 会和 `200+n`（采样槽列表）在 n=某值时撞上。先数一遍再用。

参数表最多列 64 个（内置 Test Synth 只有一个 `Level`），超出的追加一条禁用项
「还有 N 个参数没有列出」——不静默截断，用户得知道菜单不是全部。

### 三、音源面板右键看不到"音源参数的自动化"

**这不是漏了一个菜单项，是模型里没有这个位置。** 原来 `SynthSlot` 只有两条 lane：
`filter` / `level`。`automationLanes` 是 `std::array<AutomationLane, 2>`，
连"第三条"这个位置都不存在，所以菜单能列出来的东西必然只有两样。

**模型**：

```cpp
enum class SlotAutomationTarget { filter, level, plugin };
inline constexpr int numSlotAutomationTargets = 3;
```

`SynthSlot` 加 `int pluginParam = -1;` + `getPluginParam()/setPluginParam()/drivesPluginParam()`
+ `getPluginAutomation()`。**值在 curve 里，地址在 `pluginParam` 里** —— 两件套。
只存 curve 不知道压哪个参数；只存下标不知道压多少。

**发布**（`publishSchedule()`，`stable_sort` 之前）：窗口 `0 .. jmax(1, contentBeats)`、
`priority = 0`，条件 `pluginId > 0 && drivesPluginParam() && lane.isEnabled()` 且有点。
合成出来的 `PluginParamCurve` 跟编组 lane、音符包络走同一个 `automation::stackPluginParam`
（**P36 法则，不相乘第二次**）。

**建轨**只有 `ensureSlotPluginParamTrack(slotId, paramIndex)`：
先 `rack.setPluginParam`，曲线为空/仅两点才 `resetFlat(current, length)`——别抹掉用户画过的，
再 `setAutomationTarget(plugin)` + `setAutomationExpanded(true)` + `addTrack` + `revealTrack`。

`pluginParamsForSlot(slotId)` 搬到了 `MainComponent`（**非 const**，要开插件才拿得到参数表），
`pianoRoll.setPluginParamLister` 收成一行转发，不允许有第二份实现。

### 四、master 电平计不归零

**电平表是读数，不是最大值。** 所有渲染路径都用 `jmax` 往表里存块峰值（这是对的，
块内峰值不能被平均掉），问题在**没人负责让它下降**：原来只有"完全空转"那条早退分支
`decayMeters(0.90f)`。走带在跑但没有声音时（光标停在空白处、音符都放完了），
表永远钉在最后一帧 —— 正是用户看到的样子。

**改法**：衰减挪到回调开头，**无条件**执行，且按时间算。

```cpp
playback.decayMeters (numSamples);   // 紧跟 beginLiveBlock()，在 isPlaying 判断之前

const double dt = sampleRate > 0.0 ? (double) numSamples / sampleRate : 0.0;
const float factor = (float) std::pow (10.0, -2.5 * dt);   // -50 dB/s
```

`-50 dB/s` 而不是"每块乘 0.9"：后者与缓冲大小、采样率都绑死，512 帧和 256 帧落得不一样快，
那就不是一条时间曲线。断言的写法也就变成了"两种块长落到同一个值"（0.00319 / 0.00319）。

窗口侧重绘要**有条件**：新增 `hasMeters()`（遍历 `meters / layerMeters / channelMetersL/R /
masterMeters`，任一 > 1e-4 即为真），落零就停，否则 60 Hz 定时器会把一个静止窗口永远判成
"还在响"。窗口门写在 `if (!audio.isPlaying()) return;` **之前** —— 写在后面等于只有播放时才更新，
正好漏掉"停止后还在落"那一段，而那段就是用户唯一会看的。

### 五、格式版本 17 → 18

新增三个字段：`<Slot pluginparam="N">`、`<Slot autotarget="filter|level|plugin">`、
`<Automation target="plugin">`。三条 lane 全部写出。

**踩到的回归**：加了第三条 lane 之后，读取端"遍历三条、`expanded` 的那条算选中"的旧规则
恒把 target 变成 `plugin`（最后读到的那条赢），老工程读回来选中项全错，
「Synth settings, ids and automation are restored」当场红。
修法：写入端显式记录 `autotarget`，读取端优先用它；只在 `autotarget` **缺失**（v17 及更早）
时才回退旧规则。**版本判断写成"属性缺失"而不是"版本号 < 18"**——手写或迁移的工程
版本号不一定老实。

# Phase 43 — 五条需求（混音台按键 / 文件栏抬高 / 琴键音源统一 / 效果器换位置 / 四控件菜单）

选中 VST 时键盘打 VST、点钢琴窗琴键却打内置合成器；效果器机架里的效果器要能改位置；
音量/声相/静音/独奏的右键菜单各只显示自己那一行自动化，别再挂通道菜单。

前两条是"少了/矮了"，第三条是"两份实现"，第四条是"没有这个动作"，第五条是"多了一个子菜单"。
五种不同的缺，都不是加一行就完。

## 一、混音台在前台，空格和电脑键盘都哑了

**根因不是"没处理按键"，是"根本没进这条链"。** JUCE 的顶层窗口各自一棵组件树，
`MainComponent` 上装的 `KeyListener` 不在 `MixerWindow` 的链上，按键到窗口就断了，
父链往上找是找不回来的——插件窗口 P42 已经吃过一次同样的亏。

改法照抄已知可行的形状：`MixerWindow::setKeyForwarder (juce::KeyListener*)`，
**装两层**（窗口本身 + `getContentComponent()`）。只装窗口漏 content，只装 content 漏
窗口还没建 content 的那一刻（构造函数里先装窗口，`resized()` 里再补 content）。

**关键：复用同一个转发器实例，不是各建一个。** `pluginForwarder` 里记着"哪些音符是我按下的"，
两个实例就是两张键表：窗口 A 按住的音，窗口 B 松手时松不掉，最后变成永远挂着的音。
所以 `toggleMixerWindow()` 里只多一行 `mixerWindow->setKeyForwarder (&pluginForwarder);`。

转发器搬过去的不止空格，`keyPressed` 的字母音符路径也一起过去了——
用户说的"空格键播放**和**电脑键盘输入音符"是两个症状、一个病。

## 二、文件树上沿从 250 抬到 380

`MainComponent::filePaneHeight` `ui::px(250)` → `ui::px(380)`。

250 在 1.3x 下是 325 实际像素，滚动条一出来只剩 5 行可见——文件树是四栏里唯一"越深越有用"
的面板，150 行里看 5 行等于没做。380 × 1.3 = 494。

断言写成**两个数一起看**：`文件栏 494 / 图上 494 / 图层 463`。第一个是模型初值，
第二个是从分栏边界实际量出来的几何。只验模型等于自己跟自己说话——`filePaneHeight` 改了
但 `resized()` 没读它，模型照样是 494。第三个数字（图层 463）是地板：抬高不能把图层列表挤没。

## 三、选中 VST 时，键盘打 VST、琴键打合成器

**同一个规矩，写了两份。**
`MainComponent::getLiveTargetSlot()`（电脑键盘）找的是 focus 槽；
`PianoRollComponent::auditionPitchOnActiveLayer()`（琴键）走的是 `routing::layerSlotId (layer, rack)`
——它返回**图层绑定的**那台音源。用户选中 VST 时图层的绑定没变（还是内置合成器），
所以同一个"裸按键"在两个入口打向两台设备。选中 VST 恰好是用户唯一会去点琴键的时刻，
于是看起来像"琴键坏了"。

改法：把这条规矩收进 `routing::auditionSlotId (focusedSlotId, layer, rack)`，两处都调它。

```cpp
inline int auditionSlotId (int focusedSlotId, const Layer& layer, const RackModel& rack)
{
    if (const auto* slot = rack.findSlot (focusedSlotId))
        if (! slot->isSampler()) return focusedSlotId;
    return layerSlotId (layer, rack);
}
```

采样器必须排除：采样器没有音高，裸按键打到它是没声音，回到图层绑定才是本意。

断言三个数：`琴键 10 / 键盘 10 / 图层默认 1`。前两个证明两个入口一致，
第三个是**反向保护**——防止有人图省事改成"永远用 focus 槽"，那样 focus = -1 时裸按键就彻底哑了。

## 四、效果器机架里的效果器换位置

`MixerModel::moveInsert (int channel, int from, int to)`，**轮转，不是交换**：

```cpp
const auto moved = chain[(size_t) from];
if (from < to) for (int i = from; i < to; ++i) chain[(size_t) i] = chain[(size_t) i + 1];
else           for (int i = from; i > to; --i) chain[(size_t) i] = chain[(size_t) i - 1];
chain[(size_t) to] = moved;
```

交换是错的语义：从第 0 格拖到第 5 格，用户的意思"它下去、中间三个各上一位"，
交换的结果是"0 和 5 对调、中间三个原地不动"，界面上看起来像丢了一半。

UI 那边真正的难点是**点击和拖动抢同一个 `mouseDown`**。原来插槽标签在 `mouseDown` 里直接弹菜单，
鼠标一动都轮不到拖。改成三段：`mouseDown` 只记 `pressedInsertSlot`；`mouseDrag` 超过阈值才换位置
并置 `insertDragMoved`；`mouseUp` 时**没移动过**才弹菜单。

同时给右键菜单补了「上移一格 / 下移一格」（id 103/104）——拖拽在触摸板和远程桌面上不可靠，
两个入口做同一件事的成本比解释"为什么拖不动"低。

被拖中的行要上色（`insertDragMoved && pressedInsertSlot == slot`），否则拖动过程里
没有"我抓着的是哪一行"的反馈。

**断言断在音频上，不只断数组**：驱动→低通 `0.4836`，低通→驱动 `0.5352`，差 `9.6%`。
只断 `getInsert(0).type` 会让"数组换了但渲染顺序没接"整片绿——而那正是换位置唯一的意义。

## 五、四个控件各管自己

删掉 `buildChannelSubmenu` / `onChannelSubmenuChosen`（通道菜单不再挂在推子上），
新增 `fillControlMenu` / `showControlMenu`。菜单内容：标题行（`Synth A · 推子 · 0.0 dB`，
disabled，只用来告诉用户"你点的是谁的什么"）、分隔线、`复位`、`创建音量自动化`。

**拆成 fill + show 是为了让断言能读菜单。** P42 的边界里写着"弹出菜单本身无法无头截图"，
当时只能拍"菜单造出来的那一行"。这次从根上绕开：`fillControlMenu` 只管往 `PopupMenu` 里填，
`showControlMenu` 只管弹。自检拿 `juce::PopupMenu::MenuItemIterator` 遍历 fill 出来的菜单，
把文本读干净——不弹窗、不截图、不依赖鼠标。

四个控件共用一套代码，`StripControl` 枚举区分（`fader / pan / mute / solo`），
文案里带各自的名字与当前值。

## 六、id 撞车：一次自己撞自己的回归

声相/静音/独奏三个新项一开始写成 `idBase + 3/4/5`。但**卡片菜单的 `idBase = 30`**，
33/34/35 正好压在「高亮」和它邻居身上。结果「高亮」变成了 toggle——
已有的那条回归当场红：`(没亮, 再点一次 → focus -1)`。

修法：新增 `kSlotAutoTargetBase = 20000`，三项用 `idBase + 20000 + 0..2`。
而 `applySlotAutomationChoice` 必须**先判 20000 段、再判 10000 段**：
20030 同时满足"≥ 10000"，先判 10000 段就会被当成第 10030 号参数，静默指错人。

**教训写进 PITFALLS**：`PopupMenu` 的 id 空间是**扁平**的，子菜单不占 id。
新 id 必须落在与既有 `idBase` 无关的高位段，不能跟 `idBase` 做加法——你永远不知道
哪个 `idBase` 会在哪天长出第 4 个孩子。

## 七、solo 是唯一一个全局控件

静音、声相、音量都是"这条通道自己的事"，可以在 publish 期冻死。
solo 不是：`anySoloNow` 取决于**所有**通道当前是否有人独奏，而一条曲线会让它随时间移动。

所以 publish 时能冻的只有静态量，曲线必须**每块问一次**：`isAudibleAt (startBeat, anySoloNow)`，
`anySoloNow` 在 Stage 1 与 Stage 1b 的块首各扫一遍 `isSoloedAt (startBeat)`。

配套改动在 `gainAt()`：**去掉 `audible`**，只留 `fader × mute gate × level curve`。
原来 `audible` 乘在增益里，solo 又单独算一遍，两套算法会互相打架
（publish 的静态 audible 乘一次、曲线算的一次），表现为"独奏开了但音量比预期低一截"。
闸归闸、增益归增益，别混在同一行乘法里。

## 八、三条 lane 与主输出

`SlotAutomationTarget` 追加 `pan, mute, solo`，`numSlotAutomationTargets` 3 → **6**。
**只能加在枚举末尾**——枚举顺序就是 `automationLanes` 的下标，插在中间会把所有老工程
读回来的曲线挪到隔壁控件上。

master 加第三条 `mute` 曲线，`numMasterParameters` 2 → **3**（0=level, 1=pan, 2=mute）。
主输出**没有 solo**：它直接喂声卡，"独奏总线"不是一个能成立的意思，菜单里也就没有这一项。

## 九、格式版本 18 → 19

新字段：`<Automation target="pan|mute|solo">`、主输出的第三条 `mute` 曲线。
`slotTargetToText/FromText` 扩到六个名字，六条 lane 全写；master 读取端按 `target` 属性分派 0/1/2
（沿用 P42 的"属性缺失才回退旧规则"，不看版本号）。

## 断言（新增 9 条）

1. 混音台窗口在前台时，空格仍然开始/停止走带（窗口已接管按键）
2. 文件树上沿的起始高度抬高了，图层列表仍留着地板（文件栏 494 / 图上 494 / 图层 463）
