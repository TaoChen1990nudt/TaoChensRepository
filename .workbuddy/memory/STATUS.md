P98 留下的几件小事，谁接手谁看：
- **内置音源收不到 CC**。这是**结构性的**，不是没做完：内置振荡器没有 MIDI 输入的概念，
  只有 `SlotAutomationTarget::filter` 那条路。要让它响应，得决定 CC1 与既有 filter lane 是
  **叠加还是替换**——那是一个需要产品决定的问题（叠加的话「自动化画了 0.3，CC 又推到 0.9」
  该听谁的？），不该替用户拍。面板已经在 lane 上直说「内置音源，收不到 CC」。
- **CC 的时间分辨率 = 渲染块长**（几毫秒）。块内不做细分：逐样本插值只会让插件收到一串
  没有意义的中间值，而曲线形状要到下一块才真正不同。与 `applyHostedParamAutomation`
  采样一次是同一笔交易。
- **没有导出验收**。诊断原文要求「同一工程两次导出 RMS 差 < 0.1 dB」，而这台机器上没有
  可加载的 VST3，headless 也开不了声卡。已经测到的是「MIDI 事件确实被生成、且只在变化时
  生成」（纯函数 + 5 条断言），再往前一步必须有真插件。
- **三条 lane 固定**（1 / 11 / 64），不能选别的 CC。`midiCcLaneFromNumber` 会把不认识的
  编号折进 mod wheel 而不是丢掉（曲线保住，位置可能不对），所以加第四条是「改一个常量 +
  一个页签」，不是改架构。

## 最近十二轮（新会话最需要的前情）

- **P96 拼接** — 「第 1 遍的第 1–4 小节 + 第 2 遍的其余」现在能做到，接缝 4 ms 交叉淡化，
  拼完仍是一个组。三件事：**操作是「替换这个区间」不是记一张分段表**（分段表要活过存盘，
  而 take 集合是派生的、没有实体能挂它；写成替换之后三处接缝顺序无关、重复无害）；
  **接缝要重叠不要首尾相接**（进来那一段早 `fadeBeats` 开始、晚 `fadeBeats` 结束，两侧邻居

  这一份。判据要写在**块**上而不是渲染上——采样器自己在块边沿就有包络，把 fade 改成 0 渲染
  跳变只从 0.00040 变 0.00046（咬测作证）。

- **P93 引擎可观测** — 顶栏多了一块读数，答题范围是「刚才那下爆音是我还是机器」。三件事：
  **一个度量只有一个来源**——负载峰值自己算（JUCE 把峰值夹到 1.0，250% 和 100% 长得一样），
  丢帧直接用 `AudioDeviceManager::getXRunCount()`（自己在 JUCE 的计时器里面，再数一遍就重复）；
  **预算来自 `numSamples`**，所以 0 采样的回调不算一块；**计时器是 RAII**，回调四个出口
  最便宜的两个正是手写一次调用会忘的。副作用：`--snapshot` 从第 258 行起是真开着声卡的
  会话，所以整窗图里的读数是永久抖动区，比对要遮。

- **P92 拖组替换** — 「从编组栏拖一行」现在有两个答案，**是哪个由指针底下是什么决定**：
  空网格 = 再放一处（P58），压在某个组上 = 替换那一处。三件事值得记住：**锚点是目标的
  出现原点，不是指针的拍**（「落在它上面」就是「成为它」，被替换的那一处本来就有位置）；
  **命中顺序照按下的顺序**（成员优先，框在后；自己组的成员一律不算目标，否则会先删掉
  马上要插回来的东西）；**只认同图层**，跨图层要搬定义，是另一个手势。替换的不是整个组，
  是**那一处**——它没有别的出现时 `pruneEmptyGroups` 才把整行送走。

  `formatVersion` 29。三件事值得记住：**`<Transport>` 改成永远写**（"4/4 无循环"和
  "3/4 无循环"本来是同一份文档）；**读侧先无条件赋默认再查表**（老文件连 `<Transport>`
  元素都没有，`getIntAttribute` 的默认值救不了）；**三个读者读同一份**
  （标尺/复制到后一小节/节拍器重音，量化菜单那第四个在 P90 就已经收成参数）。
  两个门：标尺左上角那格（96×42，写着 `4/4`）和节拍器菜单里的「每小节拍数」。
  咬测十一处全中；`copy2` 还原会带回旧 mtime，MSBuild 于是不重编、变异漏进下一咬。
- **P90 量化** — 一个纯函数 `quantize::apply(beat, grid, strength)`：`round` 不是 `floor`，
  `>= 1.0` 早退就是夹紧（多余的 `std::min` 咬不住，删了）。改起点，不改音高与长度；
  `moved == 0` 不产生撤销步，判"动没动"用 `1e-9`（`0.1` 这种网格差 5e-17）。
  **编组两件事都要做**：先 `setOccurrenceStart(该出现最小起点)` 重锚定，再**无条件**
  `syncGroupShape`——拖动整次出现不改形状，量化改（每个成员按自己的误差归位）。
  出现原点是**存下来的数**，不走拖动路径的位移都要自己挪它，否则副本整体平移一份误差。
- **P89 CI** — 自检从 P44 起就能让进程以 1 退出，但一直没人在听。`.github/workflows/selftest.yml`
  上 `windows-2022`，门禁四条**全判在 ASCII 上**（退出码 / `[FAIL]` 数 / `ALL CHECKS PASSED` /
  PASS 数 ≥ `MIN_CHECKS`），因为日志里的中文会随控制台代码页变样。`MIN_CHECKS` 是
  "断言只增不减"唯一的执法点，加断言的那一轮必须顺手调大。**故意不跑视觉回归**：
  8 张本来会抖、其余依赖 runner 字体与 DPI，会喊狼的闸门最后一定被关掉；
  30 张图当 artifact 传。`| Tee` 之后 `$?` 是 tee 的，构建那步必须显式查 `$LASTEXITCODE`。
- **P88 节拍器与预备拍** — **点击是监听，不是声音，也不是定时器**。它混进
  `renderNextBlock` 的每个 segment、`renderInto` 里没有，所以"导出拿不到点击"是结构性的；
  每一下落在它该在的那个**采样**上（`at = (beat - fromBeat) / beatsPerSample`），
  不是块首——块首对齐听起来就是"拖了半块"。分句 `ceil (fromBeat - 1e-9)` 的 `-1e-9`
  是让正好落在块边界的那一拍**只算一次**。一击 12 ms、一块可以 46 ms ⟹ 四个声部，
  一个声部会把上一击从衰减中途切断。**预备拍不改 `positionBeats`**，"数拍期间歌曲没动"
  是构造性的；数完在**同一个块里**交接，块边界交接会塞一个 buffer 的静音。
  录音 skip 在 `RecordBuffer::begin` 里生效而不是"数完再 arm"（后者晚一个 tick，
  take 会从自己的 downbeat 之后开始）。
- **P87 循环区间** — 区间的不变量全是关于**顺序与最短**的（0.25 拍），不是关于那两个数；
  **开关与数字分开**，`loop="0"` 时位置照样写进磁盘。关闭时渲染退化成 `[0, length)` =
  P87 之前的整首循环，老行为逐位不变，这是它能上线的理由。`isUsable()` 是唯一判据，
  少判它一次，29 张视觉快照里 18 张就凭空多一个虚框。
- **P86 采样相对路径** — **模型只存绝对，相对只是文档的形式**。`toStored` 的验收标准是
  "用读盘时同一个 `resolve` 解得回原文件"，不是"字符串更短"；跨盘与符号链接自动退回绝对。
  读盘找不到**也要写绝对**，否则下一次 Ctrl+S 又把死路径存一遍。重定位只认用户挑的目录，
  弹窗默认关闭（同 P84：无头运行会动用户数据）。
- **P85 拆分与双击** — 结构重构的验收标准**不是**"能编译 + 断言全过"，是逐行比对：
  原文按非空行做多重集、和新文件做减法，允许的差异只有 `inline ` 前缀和 namespace 包裹两处。
  守卫断言保的是行为，行为可以完全正确而注释、空行、`//====` 分隔线已经错位。
  双击的语义要**分开**：名字是改名（P79），卡片其余部分是打开音源——不是一个手势两种读法；
  S/M/推子/caret 全排除，那两次点击已经各有各的活儿。插件没载入 → 答 false 且不弹窗。
- **P84 崩溃恢复** — 恢复副本**不是工程**：写它的那条路绝不能改 `currentProject`，否则下一次 Ctrl+S 会把歌存进恢复目录。
  只 offer「比工程文件严格更新」的副本；`dirtyCache` 这类缓存不算数（`hasUnsavedChanges()` 会当场重算）。
  恢复出来的会话**故意仍算未保存**，否则下一次关闭会一声不响把它扔掉。
  功能默认关闭，只有真实启动路径打开——无头运行构造同一个类，且开工第一件事就是保存工程。
- **P83 插件延迟补偿** — `pdc::solve` 解「每条路径多晚」，补偿落在汇合点而不是源头；零延迟时整条路径退化回原样。自检加了一条端到端断言：给一条静默通道强加 32 采样延迟，整个混音逐样本后移 32 采样。
- **P82 曲线路由** — `CurveBank` 把音符/采样/编组三个对象的曲线集合统一成一张有序表；旧访问器
  （`envelope` / `volumeCurve` / `automationFor` / `laneDriving`）全做成薄壳，引擎与三个编辑窗一行没动。
  磁盘上「空」= **没有 `target` 属性**（写成词会被读回 level）。删掉了 `expandedGroupTarget` 缓存字段。

## 已知边界（用户提过、还没做）

- **替换只认同图层**（P92 的边界）：拖一行到**别的图层**的组上，走的还是 P58 的「再放一处」
  （落在源组自己的图层上）。跨图层的替换要先把组的定义搬过去——那是「把组搬到这个图层」，
  另一个手势、另一个菜单项。另外替换**不改音高**：拖来的组带自己的音高，与 P58 一致。
- **量化只动起点**（P90 的边界）：长度不量化（"把长短也归位"是另一件事，也是另一个命令），
  网格只有 1/32 / 1/16 / 1/8 / 1/4 / 小节五档，**没有三连音**；自动化 lane 不受量化影响。
  量化不进工程文件（网格与强度是工具设置），`formatVersion` 的 29 是 P91 的拍号用的。
- **一拍就是一个四分音符**（P91 的边界）：菜单给 2/4 … 12/4，`meter::clamp` 收 1..16。
  **6/8 不是 `beatsPerBar = 3`**——那是三个点击，音乐里是两下；要支持得先有"附点四分"
  这个脉。变拍号（歌里换拍号）也没做：拍号现在是**一个**工程值，不是一张表。

- **丢帧数是 JUCE 的数，不是我们的**（P93）：`AudioDeviceManager::getXRunCount()` = 设备原生
  计数（有的话）+ JUCE 从回调耗时估出来的次数。判「是我还是系统」靠对比：设备自己的计数涨、
  而负载条没满，那就是系统（别的程序 / DPC）；负载先满，那就是我们。
- **CI 不跑视觉回归**（P89）：32 张图只当 artifact 上传，不逐字节比。8 张本来就会抖
  （电平表 / 播放头 / 恢复时间戳），其余依赖 runner 的字体与 DPI。要让这条进闸门，
  得先做一件事：给每张图定"允许抖多少像素 / 只比哪块区域"，而不是简单的 md5。
- **CI 只在 Windows 上跑**（P89）：macOS / Linux 能编译的那部分从来没验过（`mp3` 在非
  Windows 上本来就不可用，导出框会灰掉）。
- **节拍器与预备拍的设置不存盘**（P88）：开/关、音量、预备拍长度是 `MainComponent` 的成员，
  重启回默认（关 / 50% / 一小节）。要存就得加属性并升 `formatVersion = 30`。
- **预备拍只数不放**：数拍期间听不到歌，只有点击。想听前一小节（过门）做不到。
- **点击不跟随速度曲线在自身内部变化**：四拍统一用 take 起点那个速度。数拍不是音乐，
  但如果 take 起点正好在一个渐快段上，四拍的间隔会和后面听到的不一样。
- **节拍器/预备拍只在真机上听得出问题**：自检验的是采样级的"响没响、在哪个采样响"，
  真机上的音色、音量手感、以及预备拍与真录音的对齐还需要人耳一次。
- **循环与录音互斥，但代码没拦**（P87 的边界，P88 仍未动）：录音期间播放头回绕，后面那些音符的拍号会
  比 `recordStartBeat` **小**，而 `finishRecording()` 取 `endBeat = max(recordStartBeat, position)`，
  于是这次 take 的长度塌成 0，弹出的组是空的——**看得见，不是静默损坏**。
  一行修法是 `startRecording()` 里临时关掉循环、`finishRecording()` 再恢复；
  之所以没顺手加：`setLoopRegion` 会走 `modelChanged()`，会在录音前后各多一个"改动"。
- **导出不受循环影响**：`renderOffline` / `renderWindow` 走的是 `renderInto`，不读循环原子
  ——这是对的（导出该导整首或选区，不是那八小节），但要知道它和播放听到的不一样。
- **停止只记住"最后一次播放从哪开始"**：播放中途拖标尺换位置，停止仍回到本次播放的起点，不是新的落点。
- **刻刀一次只切点中的那一个**：不切整个选区（旧菜单行为是切选区，工具语义是切点中的对象）。
- **MP3 只在 Windows 上可用**：走 Media Foundation（系统自带）；其它平台 `mp3::isAvailable()==false`，
  导出框里 MP3 chip 灰掉。N 版 Windows 缺媒体功能包时同样灰掉，错误信息会带 HRESULT。
- **变调范围默认 ±24 半音**：老工程（v22 及更早）读进来就是 24，ratio 超过 4 的极端块会开始被夹住——
  想要旧的无限制行为就把 chip 拖到 36。
- **反转是播放期镜像**：`reversed` 只改 read 位置，源文件不变；没有「反转后重新对齐零交叉」这种精修。
- **渲染没有进度条与取消**：`ScopeRenderTask` 跑在后台线程，完成就插入；
  长选区的几秒钟里 UI 不给提示，也没法中止。
- **音符粘贴没有 streak**：P37 只修了采样。音符连按 Ctrl+V 仍落同一处（用户还没要求）。
- **VST 乐器没有双击打开界面**：只有右键菜单第 41 项，`RackPanel` 还没有 `mouseDoubleClick`。
- **粘贴/复制到后一小节都是"新增出现"**：同组的两处内容**各自独立移动**（拖哪一处只动那一处），
  因为它们是同一个定义的两个 `(groupId, groupOccurrence)`。要"整组一起动"就框选两处。
- **出现共享一条曲线**：组 lane 是绝对时间，第二处出现**不会**再画一段曲线，也**不会**按 delta 平移
  ——"同一个组"就是这个意思。要两段独立曲线就是两个组。
- **剪切→粘贴会重建组**：剪切会把榨干的组清掉，粘贴时源 id 找不到，于是新建一个同名同色的组
  ——看着一样，但它是新对象（id 变了，自动化窗口的旧条目已经先被摘掉）。
- **插件参数叠加只在单元级验证**：无头自检加载不了第三方 VST3（只有内置 `Atomic Test Synth`）。
  P41 起按键路径已经有真 VST3 断言（按下发声 / 松手当块静音 / 尾音后交还槽位）。
- **录音的已知边界**：一次按键只产出一个组，**分两次录同一段会得到两个组**（没有"接着上一组继续录"）；
  录进来的音频**不被切分**——一次按到底就是一个块，不会按静音段自动分段；录制期间**不画实时波形、不画录音头**，
  画布上只有那颗红点变亮；采样率跟随设备（48k），不与工程帧对齐；`RecordBuffer` 满了（默认 300 秒）**自己停**，
  界面上没有提示，停下来时那股手还在按的音符会被正常收尾。CC 只映射三条，其余**丢弃不猜**。
- **外部控制器那条线只验到开关与端口归属**：本机没有 MIDI 输入设备（设置页显示「已打开 0 个端口」），真硬件没测过。
- **按键不走音源滤波器**：live 声音只做增益与声相，与走带里的音色略有差别。
- **MIDI 来源不跨启动记忆**：每次启动回到代码里的默认值（P40 起是「键盘开、控制器关」）。
- **插件窗口那条按键断言只验到「窗口装上了转发器」**：真键盘在真插件界面里的手感没测过。
  转发器装了两层（窗口 + content），文本框（`juce::TextEditor`）里放行，避免插件预设名输入变成弹音符。
- **音源参数菜单最多列 64 个参数**：超出的追加一条「还有 N 个参数没有列出」。
  内置 `Atomic Test Synth` 只有一个 `Level`，真插件的长参数表只被遍历过逻辑，没看过真实排布。
- **弹出菜单本身无法无头截图**：`-slotparam` 拍的是菜单造出来的那一行，不是菜单。
   P43 起断言改成**读** `juce::PopupMenu`（`fillControlMenu` + `MenuItemIterator`），不再依赖截图。
- **混音台按键断言只验到「窗口装上了转发器 + 空格交给了走带」**，真键盘在真窗口里的手感未测。
- **效果器拖动只验到模型顺序 + 音频 RMS 变了 9.6%**，鼠标拖拽的跟手感、以及拖到槽外的行为未在真机上试过。
- **独奏自动化对 live 演奏不起作用**：`renderLive*` 用的是 publish 时的静态 `audible`，只有时间线路径按拍解算。
- **主输出没有独奏**：它直接喂声卡，"独奏总线"不是一个能成立的意思，所以主输出的独奏菜单项不存在。

headless，不需要显示器：`--snapshot` 触发 `runSelfTest()` 并导出 PNG。

```bash
build/AtomicDAW_artefacts/Release/AtomicDAW.exe --snapshot docs/phaseNN.png > docs/phaseNN.log 2>&1
```

断言总数只增不减。**新增功能要加断言并报出新的总数**（当前基准 **988**），退回去说明有东西坏了。

视觉回归：每轮入库 **36 张** `docs/pNN-*.png`（`--snapshot p98.png` 会顺带写出 35 张后缀图 + 主图；`-perf` 是 P93 新加的，`-takes` 是 P95 新加的，`-velocity` 是 P97 新加的（八根柱子的高低就是那张图的唯一判据），`-cc` 是 P98 新加的——四页签、折线、以及 HUD 里那句「内置音源，收不到 CC」；那句话只在图上，任何断言都读不回来）。
与上一轮逐字节比，**P98 是 23/35 相同**，12 张不同里 **11 张是抖动集**（同一份二进制跑两遍，两遍的集合每轮都略有出入）。`-velocity` 与 `-cc` 都在抖动集里，所以它们**只能人工看图**——两张都看过了：页签四格、柱子八根（第一根带选中描边）、HUD 里的 `0.30`、CC 折线的五个圆点与两端的平直尾部、以及那句青色的「→ 内置音源，收不到 CC」。**唯一一张真差异是 `-recovery`**，bbox `(201,93,228,102)`，就是恢复副本那一行的时间戳分钟（`17:23` vs 上一轮的 `11:06`）——它落在抖动集外面，因为两遍跑在同一分钟里。
P96 那次是 25 同 / 8 异，8 张全部落在抖动集（同一份二进制跑两遍，同样这 8 张不同）：
拼接在画面上只有「编组栏多一行名字带『拼接』的 take」和一块被切成三段的块，
4 ms 的接缝在任何缩放下都是同一条边，而那个菜单项 headless 拍不到。
P94 那 6 张（下面这段）是另一件事，留着当历史：
`-dropnote` / `-dropgroup` / `-groups` / `-loop` / `-spotlight` / 主图里那个「录音 1.wav」块
**整体左移了 3–4 px**（左边缘 112→109、275→271）。它不是渲染变了——那个块本身就是一路 take，
P94 的补偿按这台声卡报的延迟把它挪到了该在的拍上。**这 6 张因此带本机声卡延迟**，
换台机器拍出来会不一样，判「是不是回归」要先看块的位置有没有动。**同一份二进制跑两遍，本身就有
7–9 张不同**——所以判据是 bbox 的形状与位置，不是"这轮有几张不一样"。
**顶栏读数那一块要遮**（整窗帧 `(1140,30,1615,92)`；顶栏窄条帧 `(1140,6,1615,54)`）：它既含随运行
变化的负载数字，也含工程名槽里的 phase 标（P93 顺手从 P88 跳到这里）。**抖动是逐次运行的，不是逐版本的**：同一份二进制跑两次，
主图的电平表也会差三十几个像素——所以"比上一次多出几张不一样"不能当回归信号，
要看 bbox 的形状与位置。判"是不是有意的改动"用 bbox，不用 md5。
**会改状态的快照函数要么排在序列最后，要么把状态还回去**（P97 的教训：把 `-velocity` 插在序列
中间，它留下的活动层让后面三帧拍出一片空网格、留下的选区让音符丢了白边、留下的镜头让循环带
挪了位置——三张图各自都在回答「这帧要证明什么」，却全都在拍别人的状态。还回去的四件事：
活动层、混合选区、滚动、lane 开关，见 `createVelocityLaneSnapshot` 末尾；`setSelection` 与
`setSampleSelection` 各自会清掉另一半，所以还的时候要用 `setMixedSelection` 一次给）。
